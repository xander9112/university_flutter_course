# Лекция 21 — Публикация Flutter-приложения

## Подготовка к релизу

### 1. Иконка и сплэш-экран

Иконка приложения должна быть единым файлом 1024×1024 PNG. Пакеты `flutter_launcher_icons` и `flutter_native_splash` автоматически генерируют все необходимые размеры под каждую платформу.

#### flutter_launcher_icons

```yaml
# pubspec.yaml
dev_dependencies:
  flutter_launcher_icons: ^0.14.4

flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icon/icon.png"        # исходный файл 1024×1024
  web:
    generate: true
    image_path: "assets/icon/icon.png"
  windows:
    generate: true
    image_path: "assets/icon/icon.png"
    icon_size: 256
```

Запуск генерации:

```bash
flutter pub get
dart run flutter_launcher_icons
```

После выполнения команды будут обновлены все платформенные файлы иконок: `android/app/src/main/res/mipmap-*/`, `ios/Runner/Assets.xcassets/AppIcon.appiconset/` и т. д.

#### flutter_native_splash

```yaml
# pubspec.yaml
dependencies: # не dev: main.dart импортирует пакет (FlutterNativeSplash.preserve)
  flutter_native_splash: ^2.4.8

flutter_native_splash:
  color: "#1a1a2e"                          # фон сплэш-экрана (тёмно-синий)
  image: assets/images/splash_logo.png      # логотип по центру
  color_dark: "#0d0d1a"                     # фон в тёмной теме
  image_dark: assets/images/splash_logo.png
  android_12:
    # Android 12+ обрезает картинку по кругу: 960×960, логотип — внутри круга диаметром 640
    image: assets/images/splash_logo_android12.png
    color: "#1a1a2e"
```

```bash
dart run flutter_native_splash:create
```

> У пакета есть опция `fullscreen: true` — скрыть статус-бар во время загрузки. На iOS она записывает в `Info.plist` `UIStatusBarHidden`, и статус-бар пропадает во всём приложении, а не только на сплэше; на Android 12+ опция игнорируется. Поэтому в CineTrack её не используем.

Чтобы убрать сплэш-экран после инициализации приложения:

```dart
import 'package:flutter_native_splash/flutter_native_splash.dart';

void main() async {
  WidgetsBinding widgetsBinding = WidgetsFlutterBinding.ensureInitialized();
  FlutterNativeSplash.preserve(widgetsBinding: widgetsBinding);

  await configureDependencies();
  // ... другая инициализация ...

  FlutterNativeSplash.remove(); // убираем сплэш после готовности
  runApp(const MyApp());
}
```

### 2. Версионирование

```yaml
# pubspec.yaml
# Формат: MAJOR.MINOR.PATCH+BUILD_NUMBER
version: 1.0.0+1
#         │ │ │  └─ build number (целое число, увеличивается при каждой сборке)
#         │ │ └─── patch: исправление багов (1.0.0 → 1.0.1)
#         │ └───── minor: новая фича без ломающих изменений (1.0.0 → 1.1.0)
#         └─────── major: ломающие изменения (1.0.0 → 2.0.0)
```

**Правило:** Google Play и App Store требуют, чтобы build number всегда **увеличивался** при каждой новой загрузке. Нельзя загрузить версию с тем же или меньшим build number.

```bash
# Flutter позволяет задать версию при сборке
flutter build appbundle --build-name=1.2.0 --build-number=15
```

### 3. Обфускация и оптимизация

```bash
# Полная командная строка для релизной сборки Android
flutter build appbundle \
  --release \
  --obfuscate \
  --split-debug-info=build/debug-info/android \
  --target-platform android-arm,android-arm64,android-x64

# Для iOS
flutter build ipa \
  --release \
  --obfuscate \
  --split-debug-info=build/debug-info/ios
```

**`--obfuscate`** — переименовывает классы и методы в бессмысленные имена (`a`, `b`, `c`), защищая код от декомпиляции. Нельзя читать стектрейсы без debug-символов.

**`--split-debug-info`** — сохраняет отображение «обфусцированное имя → оригинальное» в папку. Нужно хранить для расшифровки крэшей.

**`--tree-shake-icons`** — автоматически удаляет иконки из шрифта MaterialIcons, которые не используются в коде. Уменьшает размер приложения на 100–300 КБ.

## Android — Google Play

### 4. Подписание приложения

Каждое Android-приложение должно быть подписано цифровым ключом. Ключ хранится в файле **keystore**.

```bash
# Генерация keystore (выполнить один раз, хранить в безопасном месте!)
keytool -genkey -v \
  -keystore ~/cinetrack-release.jks \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -alias cinetrack
```

Команда задаст несколько вопросов (имя, организация, страна) и попросит придумать пароли.

**ВАЖНО:** никогда не коммитьте `*.jks` в Git. Добавьте в `.gitignore`:

```
*.jks
android/key.properties
```

Создайте файл `android/key.properties`:

```properties
storePassword=ваш_пароль_от_keystore
keyPassword=ваш_пароль_от_ключа
keyAlias=cinetrack
storeFile=/Users/username/cinetrack-release.jks
```

Обновите `android/app/build.gradle`:

```groovy
// Читаем параметры подписи из key.properties
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    // ...

    signingConfigs {
        release {
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
            storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
            storePassword keystoreProperties['storePassword']
        }
    }

    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }
}
```

### 5. Сборка релиза

```bash
# AAB (Android App Bundle) — предпочтительный формат для Google Play
# Play Store сам соберёт оптимальный APK под каждое устройство
flutter build appbundle --release

# APK — для прямой установки на устройство или тестирования
flutter build apk --release

# APK разбитый по архитектурам (меньше размер каждого файла)
flutter build apk --split-per-abi --release
```

**AAB vs APK:**

| | AAB (App Bundle) | APK |
|-|-----------------|-----|
| Для чего | Google Play | Прямая установка |
| Размер скачивания | Меньше (Play оптимизирует) | Больше |
| Поддержка Play Store | Требуется с 2021 | Необязательно |
| Установка напрямую | Нельзя | Можно |

Готовый AAB находится в: `build/app/outputs/bundle/release/app-release.aab`

### 6. Google Play Console

1. **Регистрация:** [play.google.com/console](https://play.google.com/console) → одноразовая оплата **25$**
2. **Создание приложения:** Все приложения → Создать приложение → Заполнить название, язык, тип
3. **Метаданные приложения:**
   - Название (до 50 символов)
   - Краткое описание (до 80 символов)
   - Полное описание (до 4000 символов)
   - Скриншоты: минимум **2 скриншота** для телефона (соотношение сторон от 16:9 до 9:16)
   - Значок (512×512 PNG)
   - Графическое изображение (1024×500 JPEG/PNG)
4. **Дорожки выпуска:**
   - **Internal Testing** — до 100 тестировщиков, без проверки
   - **Closed Testing (Alpha/Beta)** — больше тестировщиков, быстрая проверка
   - **Open Testing** — открытое бета-тестирование
   - **Production** — полный выпуск, проверка 1-7 дней

```
Загрузить AAB → Internal Testing → Closed Testing → Production
```

## iOS — App Store

### 7. Требования

- **macOS** с установленным **Xcode 15+** — обязательно, без него нельзя собрать IPA
- **Apple Developer Program** — подписка **99$/год**
- Физическое устройство или симулятор для тестирования

### 8. Сертификаты и профили

В Xcode → Preferences → Accounts добавьте свой Apple ID. Xcode автоматически управляет сертификатами при включённом **Automatically manage signing**.

Для ручной настройки:
1. В **Apple Developer Portal** создайте App ID для `com.yourcompany.cinetrack`
2. Создайте **Distribution Certificate** (Apple Distribution)
3. Создайте **Provisioning Profile** типа App Store Distribution
4. Скачайте и установите в Xcode

В `ios/Runner.xcodeproj` установите:
- Bundle Identifier: `com.yourcompany.cinetrack`
- Version: `1.0.0`
- Build: `1`

### 9. Сборка и загрузка

```bash
# Сборка IPA (только на macOS)
flutter build ipa --release
```

Загрузка в App Store Connect:
1. Откройте Xcode → **Window** → **Organizer**
2. Найдите сборку → **Distribute App**
3. Выберите **App Store Connect** → **Upload**
4. Дождитесь обработки (~15-30 минут)

В **App Store Connect** ([appstoreconnect.apple.com](https://appstoreconnect.apple.com)):
1. Создайте новое приложение, укажите Bundle ID
2. Заполните метаданные: название, описание, ключевые слова
3. Добавьте скриншоты для iPhone и iPad (минимум один размер)
4. Выберите загруженную сборку
5. Нажмите **Submit for Review**

**Типичные причины отказа Apple:**
- Приложение упоминает другие платформы (Android, Google Play) в UI
- Отсутствует ссылка на политику конфиденциальности
- Функционал слишком ограничен (минимальное MVP не принимают)
- Отсутствует поддержка последних версий iOS

**Срок проверки:** обычно 1-3 рабочих дня. Первая версия часто проходит проверку дольше.

## Мониторинг продакшна

### 10. Firebase Crashlytics

Crashlytics автоматически собирает все крэши и ошибки в продакшне и отправляет подробные отчёты с контекстом.

```yaml
# pubspec.yaml
dependencies:
  firebase_core: ^4.15.0
  firebase_crashlytics: ^5.4.0
```

```dart
// main.dart
import 'package:firebase_core/firebase_core.dart';
import 'package:firebase_crashlytics/firebase_crashlytics.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();

  // Перехватываем все необработанные Flutter-ошибки
  FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;

  // Перехватываем ошибки вне Flutter-зоны (Platform errors)
  PlatformDispatcher.instance.onError = (error, stack) {
    FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
    return true;
  };

  await configureDependencies();
  runApp(const MyApp());
}
```

Ручная запись ошибок в BLoC или репозитории:

```dart
// В обработчике ошибок
on<LoadMovies>((event, emit) async {
  emit(const MoviesState.loading());
  try {
    final movies = await _getPopularMovies();
    emit(MoviesState.loaded(movies));
  } catch (e, stackTrace) {
    // Записываем неожиданную ошибку в Crashlytics
    await FirebaseCrashlytics.instance.recordError(e, stackTrace);
    emit(MoviesError('Неизвестная ошибка'));
  }
});
```

Добавление контекста к крэшу:

```dart
// Кто был залогинен во время крэша
FirebaseCrashlytics.instance.setUserIdentifier(userId);

// Кастомные атрибуты
FirebaseCrashlytics.instance.setCustomKey('screen', 'MovieDetail');
FirebaseCrashlytics.instance.setCustomKey('movie_id', movie.id.toString());

// Хлебные крошки (breadcrumbs)
FirebaseCrashlytics.instance.log('User opened movie: ${movie.title}');
```
