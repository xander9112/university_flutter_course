Это финальное задание курса. CineTrack умеет всё, что задумывалось в Задании 1, покрыт тестами, анимирован и адаптирован под разные экраны. Осталось подготовить его к реальному релизу: версия, иконка, сплэш-экран, подпись и релизная сборка.

## Задача 2. Настроить иконку приложения

1. Создайте или возьмите любое изображение 1024×1024 PNG (логотип, постер, символ плёнки).
2. Поместите его в `assets/icon/icon.png`.
3. Добавьте в `pubspec.yaml`:

```yaml
dev_dependencies:
  flutter_launcher_icons: ^0.14.0

flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icon/icon.png"
  min_sdk_android: 21
  web:
    generate: true
    image_path: "assets/icon/icon.png"
```

4. Сгенерируйте иконки:

```bash
flutter pub get
dart run flutter_launcher_icons
```

Убедитесь, что иконка обновилась в симуляторе.

## Задача 3. Настроить сплэш-экран

1. Подготовьте логотип для сплэш-экрана (рекомендуемый размер: 200×200 PNG).
2. Поместите в `assets/images/splash_logo.png`.
3. Добавьте в `pubspec.yaml`:

```yaml
dev_dependencies:
  flutter_native_splash: ^2.4.0

flutter_native_splash:
  color: "#1a1a2e"
  image: assets/images/splash_logo.png
  android_12:
    image: assets/images/splash_logo.png
    color: "#1a1a2e"
  fullscreen: true
```

4. Сгенерируйте сплэш:

```bash
dart run flutter_native_splash:create
```

5. Обновите `main()` в `main.dart` — сплэш-экран держится, пока регистрируются зависимости из Задания 16:

```dart
import 'package:flutter_native_splash/flutter_native_splash.dart';

void main() async {
  final widgetsBinding = WidgetsFlutterBinding.ensureInitialized();
  FlutterNativeSplash.preserve(widgetsBinding: widgetsBinding);

  await configureDependencies();

  FlutterNativeSplash.remove();
  runApp(
    MultiProvider(
      providers: [/* провайдеры из Задания 16 без изменений */],
      child: const MyApp(),
    ),
  );
}
```

## Задача 4. Сгенерировать keystore и настроить подписание

**Шаг 4.1.** Сгенерируйте keystore (выполнить один раз):

```bash
keytool -genkey -v \
  -keystore ~/cinetrack-release.jks \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -alias cinetrack-key
```

Команда попросит:
- Пароль для keystore и для ключа (запомните их!)
- Имя, организацию, город, страну

**Шаг 4.2.** Создайте файл `android/key.properties` (не коммитить в Git!):

```properties
storePassword=ваш_пароль_keystore
keyPassword=ваш_пароль_ключа
keyAlias=cinetrack-key
storeFile=/Users/ВашеИмя/cinetrack-release.jks
```

**Шаг 4.3.** Добавьте в `.gitignore`:

```
*.jks
android/key.properties
```

**Шаг 4.4.** Обновите `android/app/build.gradle.kts` — добавьте чтение `key.properties` и `signingConfigs`. Современный `flutter create` генерирует файлы сборки на Kotlin DSL (`.kts`); синтаксис Groovy (`build.gradle`) в них не работает.

Импорты добавьте в самое начало файла, до блока `plugins`, а чтение свойств — сразу после `plugins`:

```kotlin
import java.io.FileInputStream
import java.util.Properties

plugins {
    // ... без изменений ...
}

val keystoreProperties = Properties()
val keystorePropertiesFile = rootProject.file("key.properties")
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(FileInputStream(keystorePropertiesFile))
}

android {
    // ... существующие настройки ...

    signingConfigs {
        create("release") {
            keyAlias = keystoreProperties["keyAlias"] as String
            keyPassword = keystoreProperties["keyPassword"] as String
            storeFile = keystoreProperties["storeFile"]?.let { file(it) }
            storePassword = keystoreProperties["storePassword"] as String
        }
    }

    buildTypes {
        release {
            // замените строку signingConfigs.getByName("debug") из шаблона
            signingConfig = signingConfigs.getByName("release")
            isMinifyEnabled = true
            isShrinkResources = true
        }
    }
}
```

> Если ваш проект создан старой версией Flutter и в `android/app/` лежит `build.gradle` без `.kts`, используйте вариант на Groovy из лекции.

## Задача 5. Собрать подписанный релизный AAB

```bash
flutter build appbundle \
  --release \
  --obfuscate \
  --split-debug-info=build/debug-info/android \
  --dart-define=TMDB_API_KEY=ваш_ключ
```

Ключ TMDB подставляется при сборке (`String.fromEnvironment` из Задания 11), поэтому `--dart-define` нужен и здесь: без него релизная сборка уйдёт в магазин без ключа, и фильмы не загрузятся. Учтите, что ключ, переданный так, всё равно оказывается внутри приложения, и `--obfuscate` его не прячет — `--dart-define` защищает ключ от попадания в git, но не от извлечения из APK. Для публичного ключа TMDB с ограниченными правами это приемлемо; по-настоящему секретные ключи в мобильное приложение не кладут, а держат на своём сервере.

Если сборка прошла успешно, файл будет находиться по пути:

```
build/app/outputs/bundle/release/app-release.aab
```

Сохраните папку `build/debug-info/`: из-за `--obfuscate` стектрейсы ошибок из релизной сборки нечитаемы, и расшифровать их можно только с этими символами (командой `flutter symbolize` или в Crashlytics, если подключите его по материалам лекции).

## Задача 6. Проверить сборку на устройстве

Соберите APK для проверки на реальном устройстве или эмуляторе:

```bash
flutter build apk --release --dart-define=TMDB_API_KEY=ваш_ключ
```

Установите APK:

```bash
# Через adb
adb install build/app/outputs/flutter-apk/app-release.apk

# Или скопируйте файл на устройство и установите вручную
```

Пройдите полный пользовательский сценарий:

1. Откройте приложение — проверьте сплэш-экран и иконку
2. Дождитесь загрузки списка популярных фильмов
3. Найдите фильм через поиск
4. Откройте детальную страницу фильма
5. Добавьте фильм в избранное и поставьте ему личную оценку
6. Перейдите на вкладку «Избранное» — фильм должен быть там
7. Закройте и снова откройте приложение — избранное и оценка должны сохраниться
8. Отключите интернет — убедитесь, что данные из кэша отображаются
9. Снова включите интернет — убедитесь, что данные обновляются
