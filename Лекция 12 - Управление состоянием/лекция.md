# Лекция 12 - Управление состоянием

##  Типы состояний

https://docs.flutter.dev/data-and-backend/state-mgmt/ephemeral-vs-app

Flutter является декларативным. Это означает, что Flutter строит свой пользовательский интерфейс, отражающий текущее состояние вашего приложения:

Когда состояние вашего приложения изменяется (например, пользователь щелкает переключателем на экране настроек), вы меняете состояние, и это вызывает перерисовку пользовательского интерфейса. Нет обязательного изменения самого пользовательского интерфейса (например, widget.setText) — вы меняете состояние, и пользовательский интерфейс перестраивается с нуля.

В самом широком смысле состояние приложения — это все, что существует в памяти во время работы приложения. Сюда входят активы приложения, все переменные, которые инфраструктура Flutter хранит для пользовательского интерфейса, состояния анимации, текстур, шрифтов и так далее. Хотя это максимально широкое определение состояния допустимо, оно не очень полезно для разработки архитектуры приложения.

Во-первых, вы даже не управляете некоторыми состояниями (например, текстурами). Фреймворк обрабатывает их за вас. Таким образом, более полезным определением состояния является «любые данные, которые вам нужны для перестроения вашего пользовательского интерфейса в любой момент времени». Во-вторых, состояние, которым вы управляете самостоятельно, можно разделить на два концептуальных типа: эфемерное состояние и состояние приложения.

Эфемерное состояние (иногда называемое состоянием пользовательского интерфейса или локальным состоянием) — это состояние, которое вы можете аккуратно включить в один виджет.

Это намеренно расплывчатое определение, поэтому вот несколько примеров:

текущая страница в PageView

текущий прогресс сложной анимации 

текущая выбранная вкладка в BottomNavigationBar

Другим частям дерева виджетов редко требуется доступ к такому состоянию. Его не нужно сериализовать, и он не меняется сложным образом.

Для реализации таких локальных состояний достаточно использовать StatefullWidget.

App state

Состояние, которое не является эфемерным, которым вы хотите поделиться во многих частях вашего приложения и которое вы хотите сохранить между сеансами пользователя, — это то, что мы называем состоянием приложения (иногда также называемым общим состоянием).

Примеры состояния приложения:

Пользовательские настройки

Информация для входа

Уведомления в приложении социальной сети

Корзина в приложении электронной коммерции

Статус прочитанных/непрочитанных статей в новостном приложении

Для управления состоянием приложения вам нужно изучить свои варианты. Ваш выбор зависит от сложности и характера вашего приложения, предыдущего опыта вашей команды и многих других аспектов.

Не существует четкого универсального правила, позволяющего различать, является ли конкретная переменная эфемерной или состоянием приложения. Иногда вам придется преобразовать одно в другое. Например, вы начнете с некоторого явно эфемерного состояния, но по мере того, как ваше приложение будет расширяться, его может потребоваться перевести в состояние приложения. Этот процесс называется Lifting state up.

Для принятия решения вам может помочь следующая диаграмма 

Существует довольно много подходов для управления состояние приложения, в этом курсе мы рассмотрим такие подходы:

StatefulWidget

InheritedWidget

Это не все возможные варианты, но часто используемые в современной разработке

## setState

Как мы упоминали ранее, для локальных состояний лучше всего использовать встроенный в Flutter StatefullWidget.

Пример:

```dart
class MyHomepage extends StatefulWidget {
  const MyHomepage({super.key});
  @override
  State<MyHomepage> createState() => _MyHomepageState();
}
class _MyHomepageState extends State<MyHomepage> {
  int _index = 0;
  @override
  Widget build(BuildContext context) {
    return BottomNavigationBar(
      currentIndex: _index,
      onTap: (newIndex) {
        setState(() {
          _index = newIndex;
        });
      },
      // ... items ...
    );
  }
}
Здесь использование setState() и поля внутри класса State StatefulWidget совершенно естественно. Никакой другой части вашего приложения не требуется доступ к _index. Переменная изменяется только внутри виджета MyHomepage. И если пользователь закрывает и перезапускает приложение, вы не возражаете, что _index сбрасывается до нуля.
```

## InheritedWidget

Flutter предоставляет виджет особого типа, Inherited Widget, который можно добавить в верхнюю часть дерева приложений, и все виджеты-потомки могут наследовать (доступ) к данным этого виджета.

Мы можем создать свой класс, расширяющий InheritedWidget. Когда мы расширяем InheritedWidget, мы должны реализовать метод updateShouldNotify, который должен возвращать логическое значение. Когда Flutter пересобирает этот виджет, метод updateShouldNotify информирует Flutter, следует ли информировать виджеты, которые наследуются от него, об изменениях. Чтобы принять решение, Flutter передает этому методу экземпляр старого виджета. Мы можем сравнить этот старый виджет с вновь созданным виджетом, и если они оба точно такие же, мы можем вернуть false, иначе true (это обычный шаблон, однако это зависит от приложения, будет ли возвращаться true или false из этого метода, некоторые разработчики всегда возвращают true). Пример:

```dart
class AppDataProvider extends InheritedWidget {
  const AppDataProvider(
      {required this.appData, required super.child, super.key});
  final AppData appData;
  @override
  bool updateShouldNotify(AppDataProvider oldWidget) {
    return true;
  }
}
class AppData {
  Color backgroundColor;
  AppData({required this.backgroundColor});
  void changeBackgroundColor(Color newColor) {
    backgroundColor = newColor;
  }
}
```

Чтобы использовать унаследованный виджет, нам нужно вставить его на уровень дерева приложений, откуда мы хотим, чтобы все виджеты ниже этого уровня наследуют его данные. Обычно разработчики делают это в самом верху дерева приложений.

```dart
void main() {
  runApp(AppDataProvider(
    appData: AppData(backgroundColor: Colors.green),
    child: const MaterialApp(
      home: HomePage(),
    ),
  ));
}
```

После вставки унаследованного виджета на любом требуемом уровне мы можем использовать его в любом виджете ниже этого уровня, как показано ниже.

context.dependOnInheritedWidgetOfExactType<AppDataProvider>()?.appData.backgroundColor

Однако приведенный выше код может быть очень сложным для использования или чтения. Обычная практика, которую мы видим повсюду, включая встроенные унаследованные виджеты Flutter (такие как Theme или MediaQuery), заключается в создании статического метода класса, который возвращает данные.

```dart
class AppDataProvider extends InheritedWidget {
  const AppDataProvider(
      {required this.appData, required super.child, super.key});
  final AppData appData;
  static AppDataProvider? of(BuildContext context) =>
      context.dependOnInheritedWidgetOfExactType<AppDataProvider>();
  @override
  bool updateShouldNotify(AppDataProvider oldWidget) {
    return true;
  }
}
```

Теперь мы можем получить доступ к данным из этого виджета следующим образом.

Text(AppDataProvider.of(context)?.appData.backgroundColor.toString() ?? '')

InheritedWidget неизменны. Это означает, что все поля внутри него являются final, и мы не можем изменить его значения. Если у вас есть статические данные, которые никогда не меняются, вы можете использовать описанный выше подход. Если вы хотите, чтобы данные внутри унаследованного виджета менялись в течение жизни приложения, то вместо примитивных полей необходимо использовать объект своего класса

```dart
class AppData {
  Color backgroundColor;
  AppData({required this.backgroundColor});
  void changeBackgroundColor(Color newColor) {
    backgroundColor = newColor;
  }
}
```

С помощью него мы можем получить данные о текущем цвете и с помощью метода changeBackgroundColor изменить его в стейте.

Давайте напишем страницу, в которой будет контейнер с цветом из данных нашего InheritedWidget и кнопкой, которая меняет этот цвет на случайный.

```dart
class HomePage extends StatefulWidget {
  const HomePage({super.key});
  @override
  State<HomePage> createState() => _HomePageState();
}
class _HomePageState extends State<HomePage> {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(),
      body: Center(
          child: Container(
        width: 200,
        height: 200,
        color: AppDataProvider.of(context)?.appData.backgroundColor,
        child: Column(
          children: [
            Text(AppDataProvider.of(context)
                    ?.appData
                    .backgroundColor
                    .toString() ??
                ''),
            ElevatedButton(
                onPressed: () {
                  setState(() {
                    AppDataProvider.of(context)
                        ?.appData
                        .changeBackgroundColor(Util.randomColor());
                  });
                },
                child: const Text('Change color'))
          ],
        ),
      )),
    );
  }
}
class Util {
  static Color randomColor() {
    return Color(Random().nextInt(0xffffffff));
  }
}
```

С помощью вызова AppDataProvider.of(context)?.appData.backgroundColor читаем из InheritedWidget данные о цвете и устанавливаем его в фон контейнера,

А с помощью вызова 

```dart
   setState(() {
                    AppDataProvider.of(context)
                        ?.appData
                        .changeBackgroundColor(Util.randomColor());
                  });
```

изменяем цвет в объекте appData и перерисовываем виджет.

## Provider

Provider позволяет поместить любой объект, обладающий состоянием, в дерево виджетов и открыть к нему доступ для любого другого виджета (потомка). Также Provider помогает управлять временем жизни объектов состояний, инициализируя их с данными и выполняя очистку после того, как они будут удалены из дерева виджетов.

Provider поставляется с набором специализированных классов, благодаря которым использовать его еще удобнее. Далее мы подробнее рассмотрим каждый из этих классов.

Базовый Provider

StreamProvider

FutureProvider

ValueListenableProvider

MultiProvider

ProxyProvider

Давайте перепишем предыдущий пример с InheritedWidget с помощью пакета Provider.

В первую очередь нам нужно добавить новую зависимость в pubspec.yml

dependencies:

```dart
  provider: ^6.1.5+1
```

И выполнить команду flutter pub get

Создадим на верхнем уровне нашего приложения виджет Provider, в параметре create передадим функцию, создающую наш начальный стейт с зеленым цветом.

```dart
void main() {
  runApp(Provider(
    create: (context) => AppData(backgroundColor: Colors.green),
    child: const MaterialApp(
      home: HomePage(),
    ),
  ));
}
```

Далее изменим HomePage:

```dart
class HomePage extends StatefulWidget {
  const HomePage({super.key});
  @override
  State<HomePage> createState() => _HomePageState();
}
class _HomePageState extends State<HomePage> {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(),
      body: Center(
          child: Container(
        width: 200,
        height: 200,
        color: context.read<AppData>().backgroundColor,
        child: Column(
          children: [
            Text(context.read<AppData>().backgroundColor.toString()),
            ElevatedButton(
                onPressed: () {
                  setState(() {
                    context
                        .read<AppData>()
                        .changeBackgroundColor(Util.randomColor());
                  });
                },
                child: const Text('Change color'))
          ],
        ),
      )),
    );
  }
}
class Util {
  static Color randomColor() {
    return Color(Random().nextInt(0xffffffff));
  }
}
```

Как видите размер кода сильно уменьшился, теперь нам достаточно иметь класс содержащий стейт, который необходимо создать в Provider.

Далее с помощью метода context.read<AppData>() мы можем получить наш стейт в виджетах ниже.

Самый простой способ прочитать значение — использовать методы расширения в [BuildContext]: 

context.watch<T>(), который заставляет виджет прослушивать изменения на T 

context.read<T>(), который возвращает T, не слушая его 

context.select<T, R>(R cb(T value)), который позволяет виджету прослушивать только небольшую часть T.

Возможна ситуация, когда наш стейт будет изменен вне нашего HomePage виджета и мы никогда не узнаем об этом, так как для перерисовки состояния мы используем кнопку с вызовов setState.

Чтобы это исправить мы можем использовать ChangeNotifierProvider вместо обычного провайдера.

Для этого немного изменим наш класс с данными.

```dart
class AppData with ChangeNotifier {
  Color backgroundColor;
  AppData({required this.backgroundColor});
  void changeBackgroundColor(Color newColor) {
    backgroundColor = newColor;
    notifyListeners();
  }
}
```

Мы добавили миксин ChangeNotifier, это класс который умеет уведомлять своих подписчиков об изменении состояния.

Для этого в методе changeBackgroundColor после изменения значения цвета мы вызываем метод   notifyListeners();

Далее заменяем Provider на верхнем уровне виджетов на ChangeNotifierProvider.

```dart
void main() {
  runApp(ChangeNotifierProvider(
    create: (context) => AppData(backgroundColor: Colors.green),
    child: const MaterialApp(
      home: HomePage(),
    ),
  ));
}
```

После этого мы можем отказаться от StatefullWidgetа HomePage и сделать его StatelessWidget, так как управление перерисовкой теперь будет заниматься ChangeNotifierProvider и метод context.watch<T>

```dart
class HomePage extends StatelessWidget {
  const HomePage({super.key});
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(),
      body: Center(
          child: Container(
        width: 200,
        height: 200,
        color: context.watch<AppData>().backgroundColor,
        child: Column(
          children: [
            Text(context.watch<AppData>().backgroundColor.toString()),
            ElevatedButton(
                onPressed: () {
                  context
                      .read<AppData>()
                      .changeBackgroundColor(Util.randomColor());
                },
                child: const Text('Change color'))
          ],
        ),
      )),
    );
  }
}
```

С помощью метода  context.watch<AppData>().backgroundColor, мы подписываемся на класс AppData и слушаем его изменения. После вызова 

 context.read<AppData>().changeBackgroundColor(Util.randomColor()); происходит перестройка виджета, в котором мы подписались на AppData.

Существуют и другие типы провайдеров:

```dart
FutureProvider<T> class используется для получения результата Future и передачи его вниз по дереву.
StreamProvider<T> class используется для прослушивания стримов и передачи данных из них вниз по дереву.
```

Его основной вариант использования — предоставить большому количеству виджетов содержимое потока, не заботясь о реагировании на события. Типичным примером может быть отображение уровня заряда батареи или запрос Firebase.

```dart
ValueListenableProvider<T> class используется для прослушивания ValueListenable и передачи его значения вниз по дереву.
MultiProvider class Провайдер, который объединяет несколько провайдеров в единое линейное дерево виджетов. Он используется для повышения удобочитаемости и сокращения стандартного кода, который требует вложения нескольких уровней поставщиков.
```
