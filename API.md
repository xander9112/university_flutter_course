# API для CineTrack — замена TMDB

Требования к собственному серверу, который заменяет [The Movie Database (TMDB) API](https://developer.themoviedb.org/reference/intro/getting-started) в учебном приложении CineTrack. Если сервер выполняет всё, что описано ниже, код из Заданий 11–21 работает с ним без изменений, кроме адреса сервера (см. раздел 9). Студентам не нужно регистрироваться на themoviedb.org.

Приложение использует из TMDB совсем немного:

| Что | Где используется |
|---|---|
| `GET /3/movie/popular` — популярные фильмы | главный экран: ленты «Популярное» и «Все фильмы», pull-to-refresh (Задания 11, 13, 15, 17) |
| `GET /3/search/movie` — поиск по названию | экран поиска (Задания 11, 13, 15, 17) |
| Картинки `https://image.tmdb.org/t/p/w500/<файл>` | постеры в карточках и на экране деталей (Задания 3, 15, 17) |

Другие методы TMDB — детали фильма, жанры, актёры, `/configuration` — не используются. Названия жанров приложение берёт из своего словаря (раздел 8).

---

## 1. Общие требования

### 1.1. Адрес и протокол

- **Базовый адрес** — `https://<ваш-домен>/3`. Префикс `/3` сохраните: в коде заданий пути пишутся как `$_baseUrl/movie/popular`, где `_baseUrl` заканчивается на `/3`. Тогда при переходе меняется только домен.
- **Только HTTPS с действительным сертификатом** (например, Let's Encrypt). По умолчанию Android (API 28+) запрещает обычный HTTP, а iOS — HTTP и самоподписанные сертификаты (App Transport Security). Сервер на `http://` или с самоподписанным сертификатом без дополнительной настройки проекта работать не будет.
- **Метод** — только `GET`. Тело запроса приложение не отправляет.

### 1.2. Аутентификация

- Ключ передаётся параметром строки запроса **`api_key`** — во всех запросах, всегда. Заголовок `Authorization: Bearer` приложение не использует.
- Ключ задаётся при запуске: `flutter run --dart-define=TMDB_API_KEY=<ключ>` (Задание 11). Если сервер проверяет ключ, выдайте студентам один общий ключ курса. Если не проверяет, подойдёт любая непустая строка.
- Пустой ключ приложение начиная с Задания 15 отсекает само, ещё до запроса. Но в Задании 11 запрос с `api_key=` (пустым значением) уходит на сервер. Неверный или пустой ключ — ответ `401` (раздел 6).
- Значение ключа видно в строке запроса, поэтому **не записывайте полный URL запроса в общедоступные логи**.

### 1.3. Формат ответа

- **`Content-Type: application/json; charset=utf-8`** — обязательно.
  - Dio (Задания 17–21) разбирает тело как JSON, только если `Content-Type` — JSON. С `text/plain` или `text/html` Retrofit получит строку вместо объекта, и приложение покажет ошибку `type 'String' is not a subtype of type 'Map<String, dynamic>'`.
  - Пакет `http` (Задания 11–16) для `application/json` без `charset` сам выбирает UTF-8. Но явный `charset=utf-8` нужен, чтобы кириллица гарантированно читалась любым клиентом.
- Тело — **UTF-8**, кириллица — обычными символами или `\uXXXX`.
- Все числа — числами JSON, а не строками: `"id": 550`, а не `"id": "550"`. Подробнее о типах — в разделе 5.
- Ответ — без сжатия либо `gzip` по `Accept-Encoding`: оба клиента его понимают.

### 1.4. CORS (для Flutter Web)

Приложение собирается и под веб (Задания 14, 20), а браузер пускает запрос к другому домену только с разрешения сервера:

```http
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, OPTIONS
Access-Control-Allow-Headers: *
```

- Эти заголовки должны быть во **всех** ответах, включая ошибки `4xx` и `5xx`. Иначе браузер скроет код ошибки, и в веб-версии вместо «Ошибка загрузки: 401» будет «Нет соединения с сервером».
- На `OPTIONS` к любому пути отвечайте `204` с теми же заголовками. Обычно браузер запросы приложения не предваряет, но предварительный запрос (preflight) появится, если добавить в Dio свои заголовки.

### 1.5. Скорость

- В Dio заданы таймауты: 15 секунд на соединение и 15 на получение ответа (Задание 17). Ответ медленнее — ошибка «Нет соединения с сервером».
- Поиск отправляет запрос через 500 мс после того, как пользователь перестал печатать (Задание 11). Одновременно могут работать все студенты группы, а pull-to-refresh и перезапуски повторяют `/movie/popular`. Ответы стоит кэшировать.

## 2. `GET /3/movie/popular` — популярные фильмы

```
GET /3/movie/popular?api_key=<ключ>&language=ru-RU&page=1
```

### Параметры запроса

| Параметр | Обязателен | Пример | Описание |
|---|---|---|---|
| `api_key` | да | `abc123` | ключ (раздел 1.2) |
| `language` | приложение всегда передаёт | `ru-RU` | язык названий и описаний. Приложение всегда отправляет `ru-RU`; другие значения можно игнорировать |
| `page` | приложение всегда передаёт | `1` | номер страницы, от 1. Приложение запрашивает только `page=1`, но параметр есть в API-клиенте (Задания 15, 17). Если параметра нет, считайте его равным 1 |

Неизвестные параметры игнорируйте.

### Ответ `200 OK`

```json
{
  "page": 1,
  "results": [
    {
      "id": 27205,
      "title": "Начало",
      "overview": "Кобб — талантливый вор, лучший из лучших в опасном искусстве извлечения...",
      "poster_path": "/9gk7adHYeDvHkCSEqAvQNLV5Uge.jpg",
      "backdrop_path": "/8ZTVqvKDQ8emSGUEMjsS4yHAwrp.jpg",
      "vote_average": 8.4,
      "release_date": "2010-07-15",
      "genre_ids": [28, 878, 12]
    }
  ],
  "total_pages": 500,
  "total_results": 10000
}
```

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `results` | массив объектов «Фильм» (раздел 5) | **да** | фильмы страницы. Может быть пустым, но не `null` и не отсутствовать |
| `page` | целое | желательно | номер возвращённой страницы. Если поля нет, Задание 17 считает его равным 1 |
| `total_pages` | целое | желательно | всего страниц. Если поля нет, Задание 17 считает его равным 1 |
| `total_results` | целое | нет | всего фильмов. Приложение поле не читает, но оно есть в TMDB |

**Сколько фильмов отдавать.** У TMDB на странице 20 фильмов, удобнее так же. Нужно не меньше 5: лента «Популярное» показывает первые 5. На главный экран идёт вся первая страница.

**Порядок.** По популярности, по убыванию. Порядок должен быть стабильным: pull-to-refresh перезапрашивает список, и если фильмы каждый раз перемешиваются, это выглядит как ошибка.

**Страница за пределами диапазона.** Если `page` больше `total_pages`, верните `200` с пустым `results` и `page` из запроса. Если `page` < 1 или не число, верните `422` (раздел 6).

## 3. `GET /3/search/movie` — поиск

```
GET /3/search/movie?api_key=<ключ>&language=ru-RU&query=%D0%9C%D0%B0%D1%82%D1%80%D0%B8%D1%86%D0%B0
```

### Параметры запроса

| Параметр | Обязателен | Пример | Описание |
|---|---|---|---|
| `api_key` | да | `abc123` | ключ |
| `query` | да | `Матрица` | строка поиска (см. ниже про кодирование) |
| `language` | приложение всегда передаёт | `ru-RU` | как в разделе 2 |
| `page` | нет | `1` | приложение не передаёт. Если параметра нет, считайте его равным 1 |

### Кодирование `query`

Значение приходит в percent-encoding UTF-8, и два клиента кодируют пробел по-разному:

| Клиент | Задания | `Матрица 2` в запросе |
|---|---|---|
| `http` + `Uri.encodeComponent` | 11–16 | `query=%D0%9C%D0%B0%D1%82%D1%80%D0%B8%D1%86%D0%B0%202` |
| Dio + Retrofit `@Query` | 17–21 | `query=%D0%9C%D0%B0%D1%82%D1%80%D0%B8%D1%86%D0%B0+2` |

Сервер должен декодировать **и `%20`, и `+` как пробел**: так работает стандартный разбор строки запроса (`application/x-www-form-urlencoded`) в большинстве фреймворков. Если `+` не декодировать, поиск из двух слов в Заданиях 17–21 ничего не найдёт.

### Поиск

- Без учёта регистра, по подстроке названия. Ищите и по русскому `title`, и по оригинальному названию: студенты будут искать и «Матрица», и «Matrix».
- Пробелы в начале и в конце запроса приложение обрезает само (Задание 13). Сервер на всякий случай может обрезать их тоже.
- Пустой запрос приложение не отправляет. Если он всё же пришёл (или `query` нет), верните `200` с пустым `results`, как TMDB.
- Ничего не найдено — `200` с пустым `results`, а не `404`. Экран поиска сам покажет «Ничего не найдено».

### Ответ `200 OK`

Формат тот же, что у `/movie/popular` (раздел 2): `page`, `results`, `total_pages`, `total_results`. Приложение показывает только первую страницу — до 20 фильмов.

## 5. Объект «Фильм»

Код всех заданий разбирает объект по одним и тем же правилам (`Movie.fromJson` в Задании 11, `MovieDto.fromJson` в Заданиях 15 и 17). Нарушение типа обязательного поля ломает **весь** ответ: при разборе бросается исключение, и вместо списка экран показывает ошибку.

| Поле | Тип | `null` / нет поля | Как используется |
|---|---|---|---|
| `id` | **целое** | **нельзя** | ключ карточки, избранного и оценок. Уникален среди всех фильмов и не меняется между запросами, иначе избранное и личные оценки «потеряются». Именно целое: `27205`, не `"27205"` и не `27205.0` — в Задании 11 стоит `json['id'] as int` |
| `title` | строка | **нельзя** | название. Должно быть непустым: для фильма без перевода отдавайте оригинальное название, как TMDB. В Задании 11 стоит `as String`, `null` ломает разбор |
| `overview` | строка | можно | описание. Если описания нет, лучше `null`, чем `""`: на `null` экран деталей показывает «Описание отсутствует», а на `""` — пустое место |
| `poster_path` | строка | можно | **путь** к постеру, а не полный URL: начинается с `/`, например `/9gk7adHYeDvHkCSEqAvQNLV5Uge.jpg`. Приложение само дописывает к нему `https://image.tmdb.org/t/p/w500` (раздел 7). При `null` показывается заглушка |
| `backdrop_path` | строка | можно | путь к фоновому кадру, формат как у `poster_path`. Читается и сохраняется в кэш, на экране пока не показывается |
| `vote_average` | число | можно | рейтинг от 0 до 10, целое или дробное: `8`, `8.4`. Показывается с одним знаком после точки. Не строка. При `null` вместо рейтинга прочерк |
| `release_date` | строка | можно | дата `ГГГГ-ММ-ДД`. Год — первые 4 символа, при более короткой строке — «N/A». Неизвестная дата — `""` или `null` |
| `genre_ids` | массив **целых** | можно (как `[]`) | id жанров TMDB (раздел 8). Элементы — целые, не строки. Нет поля или `null` — жанров нет |

Остальные поля TMDB — `original_title`, `original_language`, `popularity`, `vote_count`, `adult`, `video` — приложение не читает. Их можно отдавать для совместимости с TMDB, лишние поля ничего не ломают.

**Имена полей — только `snake_case`**, как у TMDB: `poster_path`, а не `posterPath`. Задание 17 включает `FieldRename.snake`, и поля в `camelCase` читались бы как отсутствующие.

## 6. Ошибки

Приложение смотрит только на HTTP-код, тело ошибки не читает.

| Код | Когда | Что увидит пользователь |
|---|---|---|
| `401 Unauthorized` | `api_key` нет, он пустой или неверный | «Ошибка загрузки: 401» (поиск в Задании 11 — «Ошибка поиска: 401») |
| `404 Not Found` | неизвестный путь | «Ошибка загрузки: 404» |
| `422 Unprocessable Entity` | неверный параметр (`page=0`, `page=abc`) | «Ошибка загрузки: 422» |
| `429 Too Many Requests` | превышен лимит запросов (если он есть) | «Ошибка загрузки: 429» |
| `5xx` | сбой сервера | «Ошибка загрузки: 500» и т. п. |

Если сеть недоступна, поиск DNS не удался или вышел таймаут, приложение покажет «Нет соединения с сервером». Начиная с Задания 14 оно подставит список из кэша.

Тело ошибки лучше делать в формате TMDB, чтобы было удобно отлаживать (например, через `curl`):

```json
{
  "success": false,
  "status_code": 7,
  "status_message": "Invalid API key: You must be granted a valid key."
}
```

Коды `status_code` у TMDB: `7` — неверный ключ, `34` — ресурс не найден, `22` — неверная страница (`page`), `25` — превышен лимит запросов.

Код `200` отдавайте только с телом из раздела 2. Не отвечайте `200` со страницей ошибки в HTML или с `{"error": ...}`: приложение попытается разобрать такое тело как список фильмов и упадёт с непонятным сообщением.

## 7. Картинки

Полный адрес постера приложение собирает так:

```dart
'https://image.tmdb.org/t/p/w500$posterPath'   // Задания 3, 15, 17
```

Есть два варианта.

**А. Оставить картинки на `image.tmdb.org`.** Если сервер берёт данные из TMDB, то есть сам ходит в TMDB со своим ключом и кэширует, отдавайте в `poster_path` пути TMDB как есть. Картинки `image.tmdb.org` доступны без ключа и регистрации, поэтому в приложении ничего менять не нужно. Нужно только, чтобы этот домен открывался у студентов.

**Б. Раздавать картинки со своего сервера.** Тогда:

- путь — `GET /t/p/w500/<файл>`, без префикса `/3` и без `api_key`. Например, `https://<ваш-домен>/t/p/w500/9gk7adHYeDvHkCSEqAvQNLV5Uge.jpg`;
- в `poster_path` и `backdrop_path` — пути вида `/<файл>.jpg`;
- ответ `200` с `Content-Type: image/jpeg` (или `image/png`, `image/webp`), картинка шириной 500 px. Постеры TMDB — 2:3, то есть 500×750;
- нет файла — `404`. Приложение покажет заглушку;
- **`Access-Control-Allow-Origin: *` и для картинок**: Flutter Web загружает картинки через `fetch`/`XMLHttpRequest`, и без CORS постеры в веб-версии не появятся;
- желательно `Cache-Control: public, max-age=86400`.

В варианте Б студенты в одном месте меняют `https://image.tmdb.org` на адрес сервера (раздел 9).

## 10. Проверка сервера

Сервер совместим с приложением, если выполняется всё ниже:

```bash
S=https://<ваш-домен>/3
K=<ключ>

# 1. Популярные: 200, JSON, UTF-8, массив results из 5+ фильмов
curl -si "$S/movie/popular?api_key=$K&language=ru-RU&page=1" | head -20

# 2. Поиск с кириллицей и пробелом — обоими способами кодирования
curl -s "$S/search/movie?api_key=$K&language=ru-RU&query=%D0%9C%D0%B0%D1%82%D1%80%D0%B8%D1%86%D0%B0%202"
curl -s "$S/search/movie?api_key=$K&language=ru-RU&query=%D0%9C%D0%B0%D1%82%D1%80%D0%B8%D1%86%D0%B0+2"

# 3. Ничего не найдено: 200 и пустой results
curl -si "$S/search/movie?api_key=$K&language=ru-RU&query=zzzzzz" | head -1

# 4. Без ключа и с неверным ключом: 401
curl -si "$S/movie/popular?language=ru-RU&page=1" | head -1
curl -si "$S/movie/popular?api_key=wrong&language=ru-RU&page=1" | head -1
```
