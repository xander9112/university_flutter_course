# Задание 12 — Clean Architecture: реструктуризация проекта

## Контекст

Продолжаем разработку **CineTrack**. Сейчас файлы проекта разложены плоско в папках `lib/services`, `lib/models`, `lib/screens`. При росте приложения это приводит к запутанным зависимостям. В этом задании вы реструктурируете проект по принципам **Clean Architecture**: три чётких слоя с однонаправленными зависимостями.

## Задачи

### 1. Создать `Failure` в `core/`

Создайте `lib/core/errors/failure.dart`:

```dart
abstract class Failure {
  final String message;
  const Failure(this.message);
}

class NetworkFailure extends Failure {
  const NetworkFailure(super.message);
}

class CacheFailure extends Failure {
  const CacheFailure(super.message);
}
```

### 2. Создать `Movie` Entity в `domain/`

Сущность в domain-слое — это **чистый Dart-класс без зависимостей от сети или БД**:

```dart
// lib/features/movies/domain/entities/movie.dart
class Movie {
  final int id;
  final String title;
  final String? overview;
  final String? posterPath;
  final String? backdropPath;
  final double? voteAverage;
  final String releaseDate;

  const Movie({
    required this.id,
    required this.title,
    this.overview,
    this.posterPath,
    this.backdropPath,
    this.voteAverage,
    required this.releaseDate,
  });

  String get year => releaseDate.length >= 4 ? releaseDate.substring(0, 4) : 'N/A';
  String get posterUrl => posterPath != null ? 'https://image.tmdb.org/t/p/w500$posterPath' : '';
}
```

### 5. Создать `MovieDto` в `data/`

DTO отвечает за сериализацию — это обязанность data-слоя:

```dart
// lib/features/movies/data/models/movie_dto.dart
import '../../domain/entities/movie.dart';

class MovieDto extends Movie {
  const MovieDto({
    required super.id,
    required super.title,
    super.overview,
    super.posterPath,
    super.backdropPath,
    super.voteAverage,
    required super.releaseDate,
  });

  factory MovieDto.fromJson(Map<String, dynamic> json) {
    return MovieDto(
      id: json['id'] as int,
      title: json['title'] as String,
      overview: json['overview'] as String?,
      posterPath: json['poster_path'] as String?,
      backdropPath: json['backdrop_path'] as String?,
      voteAverage: (json['vote_average'] as num?)?.toDouble(),
      releaseDate: json['release_date'] as String? ?? '',
    );
  }

  Map<String, dynamic> toJson() => {
    'id': id,
    'title': title,
    'overview': overview,
    'poster_path': posterPath,
    'backdrop_path': backdropPath,
    'vote_average': voteAverage,
    'release_date': releaseDate,
  };
}
```

### 6. Создать `MovieRepositoryImpl`

```dart
// lib/features/movies/data/repositories/movie_repository_impl.dart
import '../../domain/entities/movie.dart';
import '../../domain/repositories/movie_repository.dart';
import '../datasources/movie_remote_datasource.dart';
import '../datasources/movie_local_datasource.dart';

class MovieRepositoryImpl implements MovieRepository {
  final MovieRemoteDataSource remoteDataSource;
  final MovieLocalDataSource localDataSource;

  const MovieRepositoryImpl({
    required this.remoteDataSource,
    required this.localDataSource,
  });

  @override
  Future<List<Movie>> getPopularMovies({int page = 1}) async {
    try {
      final movies = await remoteDataSource.getPopularMovies(page: page);
      await localDataSource.cacheMovies(movies);
      return movies;
    } catch (_) {
      return localDataSource.getCachedMovies();
    }
  }

  @override
  Future<List<Movie>> searchMovies(String query) =>
      remoteDataSource.searchMovies(query);
}
```

### 7. Обновить `MoviesBloc` для работы с Use Cases

```dart
class MoviesBloc extends Bloc<MoviesEvent, MoviesState> {
  final GetPopularMovies getPopularMovies;
  final SearchMovies searchMovies;

  MoviesBloc({
    required this.getPopularMovies,
    required this.searchMovies,
  }) : super(MoviesInitial()) {
    on<LoadMovies>((event, emit) async {
      emit(MoviesLoading());
      try {
        final movies = await getPopularMovies();
        emit(MoviesLoaded(movies));
      } catch (e) {
        emit(MoviesError(e.toString()));
      }
    });
    // ... аналогично для других событий
  }
}
```

## Критерии выполнения

- [ ] Проект разбит на три слоя: `domain`, `data`, `presentation`
- [ ] `Movie` entity в domain не содержит `fromJson`/`toJson`
- [ ] `MovieDto` в data содержит сериализацию
- [ ] `MovieRepository` — абстрактный интерфейс в domain
- [ ] `MovieRepositoryImpl` в data реализует интерфейс
- [ ] `MoviesBloc` зависит только от use cases, а не от `MovieApiService` напрямую
- [ ] Зависимости направлены строго внутрь: `presentation → domain ← data`
