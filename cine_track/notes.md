# Задание 1 — ответы на вопросы

**За что отвечает директория `lib/`?**
Здесь лежит весь Dart-код приложения. Точка входа — `lib/main.dart` с функцией `main()`, которая вызывает `runApp()`. Все экраны, виджеты, модели и сервисы CineTrack будут располагаться внутри `lib/`.

**Что описывает файл `pubspec.yaml`?**
Это манифест проекта: имя пакета (`cine_track`), описание, версия приложения (`1.0.0+1` — версия и номер сборки), требуемая версия Dart SDK, зависимости (`dependencies`) и зависимости для разработки (`dev_dependencies`), а также ресурсы — шрифты, изображения (секция `flutter:`). После изменения зависимостей выполняется `flutter pub get`.

**Зачем нужны директории `android/` и `ios/`?**
Это нативные проекты-обёртки для каждой платформы: Gradle-проект для Android и Xcode-проект для iOS. В них настраиваются идентификатор приложения, иконки, разрешения (`AndroidManifest.xml`, `Info.plist`), подпись релизной сборки. Flutter-код из `lib/` встраивается в эти проекты при сборке. Аналогично `web/` — обёртка для веб-версии.

**Что происходит в папке `build/` при запуске проекта?**
В `build/` Flutter складывает результаты сборки: скомпилированный Dart-код, ресурсы, промежуточные файлы Gradle/Xcode и итоговые артефакты (`.apk`, `.app`, веб-бандл). Папка генерируется автоматически при каждой сборке, её можно удалить командой `flutter clean`, и она не хранится в Git (указана в `.gitignore`).

# Задание 7 — эксперимент с ключами

Для эксперимента `MovieCard` временно сделан `StatefulWidget`: тап по карточке подсвечивает её фон. Отмечены карточки **Inception** и **Interstellar**, после чего порядок списка изменён (перевёрнут — так результат воспроизводим, с `shuffle()` поведение то же).

| Вариант элемента списка | Какие карточки подсвечены после перестановки |
|---|---|
| Без ключа: `MovieCard(movie: movie)` | **Dune, Parasite** — отметки остались на первых двух позициях и «приклеились» к чужим фильмам |
| `ValueKey(movie.id)` в `ListView.builder` без `findChildIndexCallback` | **ни одной** — отметки пропали |
| `ValueKey(movie.id)` + `findChildIndexCallback` | **Inception, Interstellar** — отметки переехали вместе со своими фильмами |

**Почему так.**
- Без ключа Flutter сопоставляет старые и новые виджеты по позиции и типу. На позиции 0 по-прежнему стоит `MovieCard`, поэтому её `State` (с отметкой) переиспользуется, хотя фильм там уже другой.
- С ключом Flutter понимает, что на позиции 0 теперь другой элемент, и не переиспользует чужое состояние. Но `ListView.builder` строит элементы лениво, по индексу, и сам не знает, на какой индекс переехал элемент с данным ключом. Поэтому старый элемент удаляется, а новый создаётся с чистым состоянием.
- `findChildIndexCallback` сообщает списку новый индекс элемента по его ключу. Тогда `State` переносится на новую позицию — состояние следует за фильмом.

**Вывод:** в динамическом списке, который меняет порядок, корневому виджету элемента (`Dismissible`) нужен уникальный `ValueKey(movie.id)`, а `ListView.builder` — `findChildIndexCallback`. Оба добавлены в `HomeScreen`. После эксперимента `MovieCard` возвращён в `StatelessWidget`.
