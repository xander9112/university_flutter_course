# Лекция 18 - Основы тестирования

## Основы Unit тестирования

Unit  тесты удобны для проверки поведения отдельной функции, метода или класса. Пакет test предоставляет базовую структуру для написания модульных тестов, а пакет flutter_test предоставляет дополнительные утилиты для тестирования виджетов.

Пакет test предоставляет основные функции для написания тестов в Dart. Это лучший подход при написании пакетов, используемых веб-приложениями, серверами и приложениями Flutter. Чтобы добавить тестовый пакет в качестве зависимости от разработчиков, запустите flutter pub add:

flutter pub add dev:test

Создадим два файла: counter.dart и counter_test.dart.

Файл counter.dart содержит класс, который вы хотите протестировать, и находится в папке lib. Файл counter_test.dart содержит сами тесты и находится в папке test.

Как правило, тестовые файлы должны находиться в папке test, расположенной в корне вашего приложения или пакета Flutter. Файлы тестов всегда должны заканчиваться на _test.dart, это соглашение используется test раннером при поиске тестов.

counter_app/

```dart
  lib/
    counter.dart
  test/
    counter_test.dart
```

Далее вам понадобится «юнит» для тестирования. «юнит» — это другое название функции, метода или класса. В этом примере создайте класс Counter внутри файла lib/counter.dart. Он отвечает за увеличение и уменьшение значения, начиная с 0.

```dart
class Counter {
  int value = 0;
  void increment() => value++;
  void decrement() => value--;
}
```

Внутри файла counter_test.dart напишите первый модульный тест. Тесты определяются с помощью функции test верхнего уровня, и вы можете проверить правильность результатов с помощью функции expect верхнего уровня. Обе эти функции находятся в пакете test.

// Import the test package and Counter class

```dart
import 'package:counter_app/counter.dart';
import 'package:test/test.dart';
void main() {
  test('Counter value should be incremented', () {
    final counter = Counter();
    counter.increment();
    expect(counter.value, 1);
  });
}
```

Если у вас есть несколько тестов, связанных друг с другом, объедините их с помощью функции group, предоставляемой пакетом test.

```dart
import 'package:counter_app/counter.dart';
import 'package:test/test.dart';
void main() {
  group('Counter', () {
    test('value should start at 0', () {
      expect(Counter().value, 0);
    });
    test('value should be incremented', () {
      final counter = Counter();
      counter.increment();
      expect(counter.value, 1);
    });
    test('value should be decremented', () {
      final counter = Counter();
      counter.decrement();
      expect(counter.value, -1);
    });
  });
}
```

Теперь, когда у вас есть класс Counter и тесты к нему, вы можете запустить тестирование.

Плагины Flutter для IntelliJ и VSCode поддерживают выполнение тестов. Часто это лучший вариант при написании тестов, поскольку он обеспечивает удобство, а также возможность устанавливать точки останова для отладки тестов.

Выберите в меню Run

Вы также можете использовать терминал для запуска тестов, выполнив следующую команду из корня проекта:

Или укажите конкретный файл тестов для их запуска:

## Основы Widget тестирования

Для тестирования классов виджетов вам понадобится несколько дополнительных инструментов, предоставляемых пакетом flutter_test, который поставляется с Flutter SDK.

Пакет flutter_test предоставляет следующие инструменты для тестирования виджетов:

WidgetTester позволяет создавать виджеты и взаимодействовать с ними в тестовой среде.

Функция testWidgets() автоматически создает новый WidgetTester для каждого теста и используется вместо обычной функции test().

Классы Finder позволяют искать виджеты в тестовой среде.

Константы Matcher для конкретных виджетов помогают проверить, находит ли Finder виджет или несколько виджетов в тестовой среде.

Прежде чем писать тесты, включите зависимость flutter_test в раздел dev_dependencies файла pubspec.yaml. При создании нового проекта Flutter с помощью инструментов командной строки или редактора кода эта зависимость уже должна быть на месте.

Далее создайте виджет для тестирования.

```dart
class MyWidget extends StatelessWidget {
  const MyWidget({
    super.key,
    required this.title,
    required this.message,
  });
  final String title;
  final String message;
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Flutter Demo',
      home: Scaffold(
        appBar: AppBar(
          title: Text(title),
        ),
        body: Center(
          child: Text(message),
        ),
      ),
    );
  }
}
```

Теперь, имея виджет для тестирования, создадим для него первый тест. Для этого используем функцию testWidgets(), предоставляемую пакетом flutter_test. Функция testWidgets позволяет определить тест виджета и создает WidgetTester для работы.

Затем создайте MyWidget внутри тестовой среды, используя метод pumpWidget(), предоставленный WidgetTester. Метод pumpWidget создает и отображает предоставленный виджет. Создайте экземпляр MyWidget, который отображает «T» в качестве заголовка и «M» в качестве сообщения.

```dart
void main() {
  testWidgets('MyWidget has a title and message', (tester) async {
    // Create the widget by telling the tester to build it.
    await tester.pumpWidget(const MyWidget(title: 'T', message: 'M'));
  });
}
```

После первоначального вызова pumpWidget() WidgetTester предоставляет дополнительные способы перестроения того же виджета. Это полезно, если вы работаете с StatefulWidget или анимацией.

```dart
Например, нажатие кнопки вызывает setState(), но Flutter не будет автоматически перестраивать ваш виджет в тестовой среде. Используйте один из следующих способов, чтобы попросить Flutter перестроить виджет.
```

tester.pump(Duration duration)

Планирует кадр и запускает перестроение виджета. Если указана продолжительность, она переводит часы на эту величину и планирует кадр. Он не планирует несколько кадров, даже если продолжительность превышает один кадр.

tester.pumpAndSettle()

Неоднократно вызывает pump() с заданной продолжительностью до тех пор, пока больше не будет запланированных кадров. Этот метод, по сути, ждет завершения всех анимаций. Эти методы обеспечивают детальный контроль над жизненным циклом виджетов, что особенно полезно при тестировании.

С виджетом в тестовой среде найдите в дереве виджетов текстовые виджеты заголовка и сообщения с помощью Finder. Это позволяет проверить правильность отображения виджетов. Для этого используйте метод find() верхнего уровня, предоставляемый пакетом flutter_test, для создания Finders. Поскольку вы знаете, что ищете текстовые виджеты, используйте метод find.text().

```dart
void main() {
  testWidgets('MyWidget has a title and message', (tester) async {
    await tester.pumpWidget(const MyWidget(title: 'T', message: 'M'));
    // Create the Finders.
    final titleFinder = find.text('T');
    final messageFinder = find.text('M');
  });
}
```

Наконец, убедитесь, что текстовые виджеты заголовка и сообщения отображаются на экране, используя константы Matcher, предоставленные flutter_test. Классы Matcher являются основной частью тестового пакета и предоставляют общий способ проверки соответствия заданного значения ожиданиям. Убедитесь, что виджеты появляются на экране ровно один раз. Для этого используйте findsOneWidget Matcher.

```dart
void main() {
  testWidgets('MyWidget has a title and message', (tester) async {
    await tester.pumpWidget(const MyWidget(title: 'T', message: 'M'));
    final titleFinder = find.text('T');
    final messageFinder = find.text('M');
    // Use the `findsOneWidget` matcher provided by flutter_test to verify
    // that the Text widgets appear exactly once in the widget tree.
    expect(titleFinder, findsOneWidget);
    expect(messageFinder, findsOneWidget);
  });
}
```

В дополнение к findsOneWidget, flutter_test предоставляет дополнительные matchers для общих случаев.

findsNothing

Проверяет, что виджеты не найдены.

findsWidgets

Проверяет, найден ли один или несколько виджетов.

findsNWidgets

Проверяет, найдено ли определенное количество виджетов.

matchesGoldenFile

Проверяет, соответствует ли рендеринг виджета конкретному растровому изображению (тестирование Golden File).

Обработка скрола

Во многих приложениях есть списки контента, от почтовых клиентов до музыкальных приложений и так далее. Чтобы убедиться, что списки содержат ожидаемый контент с помощью тестов виджетов, вам нужен способ прокрутки списков для поиска определенных элементов.

```dart
import 'package:flutter/material.dart';
void main() {
  runApp(MyApp(
    items: List<String>.generate(10000, (i) => 'Item $i'),
  ));
}
class MyApp extends StatelessWidget {
  final List<String> items;
  const MyApp({super.key, required this.items});
  @override
  Widget build(BuildContext context) {
    const title = 'Long List';
    return MaterialApp(
      title: title,
      home: Scaffold(
        appBar: AppBar(
          title: const Text(title),
        ),
        body: ListView.builder(
          // Add a key to the ListView. This makes it possible to
          // find the list and scroll through it in the tests.
          key: const Key('long_list'),
          itemCount: items.length,
          itemBuilder: (context, index) {
            return ListTile(
              title: Text(
                items[index],
                // Add a key to the Text widget for each item. This makes
                // it possible to look for a particular item in the list
                // and verify that the text is correct
                key: ValueKey('item_${index}_text'),
              ),
            );
          },
        ),
      ),
    );
  }
}
```

В этом примере прокрутим список элементов и убедимся, что определенный элемент существует в списке. Класс WidgetTester предоставляет метод scrollUntilVisible(), который прокручивает список до тех пор, пока определенный виджет не станет видимым. Это полезно, потому что высота элементов в списке может меняться в зависимости от устройства.

Вместо того, чтобы предполагать, что вы знаете высоту всех элементов в списке или что конкретный виджет отображается на всех устройствах, метод scrollUntilVisible() многократно прокручивает список элементов, пока не найдет то, что ищет.

В следующем коде показано, как использовать метод scrollUntilVisible() для просмотра списка в поисках определенного элемента. 

```dart
import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:scrolling/main.dart';
void main() {
  testWidgets('Counter increments smoke test', (tester) async {
    // Build our app and trigger a frame.
    await tester.pumpWidget(MyApp(
      items: List<String>.generate(10000, (i) => 'Item $i'),
    ));
    final listFinder = find.byType(Scrollable);
    final itemFinder = find.byKey(const ValueKey('item_50_text'));
    // Scroll until the item to be found appears.
    await tester.scrollUntilVisible(
      itemFinder,
      500.0,
      scrollable: listFinder,
    );
    // Verify that the item contains the correct text.
    expect(itemFinder, findsOneWidget);
  });
}
```

## Основы Integration тестирования

Модульные тесты и тесты виджетов удобны для тестирования отдельных классов, функций или виджетов. Однако они, как правило, не проверяют, как отдельные части работают вместе в целом, и не измеряют производительность приложения, работающего на реальном устройстве. Эти задачи выполняются с помощью интеграционных тестов.

Интеграционные тесты пишутся с использованием пакета integration_test, предоставляемого SDK.

Сначала создайте приложение для тестирования. В этом примере протестируем приложение счетчика, созданное командой flutter create. Это приложение позволяет пользователю нажать на кнопку, чтобы увеличить счетчик.

Затем используйте пакеты integration_test и flutter_test для написания интеграционных тестов. Добавьте эти зависимости в раздел dev_dependencies файла pubspec.yaml приложения, указав Flutter SDK в качестве местоположения пакета.

Создайте новый каталог integration_test с пустым файлом app_test.dart:

counter_app/

```dart
  lib/
    main.dart
  integration_test/
    app_test.dart
```

Теперь вы можете писать тесты. Это включает в себя три шага: 

Инициализация IntegrationTestWidgetsFlutterBinding, службы, которая выполняет тесты на физическом устройстве. 

Взаимодействие и тестирование виджетов с помощью класса WidgetTester. 

Тестирование важных сценариев.

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:integration_test/integration_test.dart';
import 'package:introduction/main.dart';
void main() {
  IntegrationTestWidgetsFlutterBinding.ensureInitialized();
  group('end-to-end test', () {
    testWidgets('tap on the floating action button, verify counter',
        (tester) async {
      // Load app widget.
      await tester.pumpWidget(const MyApp());
      // Verify the counter starts at 0.
      expect(find.text('0'), findsOneWidget);
      // Finds the floating action button to tap on.
      final Finder fab = find.byTooltip('Increment');
      // Emulate a tap on the floating action button.
      await tester.tap(fab);
      // Trigger a frame.
      await tester.pumpAndSettle();
      // Verify the counter increments by 1.
      expect(find.text('1'), findsOneWidget);
    });
  });
}
```

Процесс запуска интеграционных тестов зависит от платформы, на которой вы тестируете. Вы можете протестировать мобильную платформу или Web.

Для тестирования на реальном устройстве iOS/Android сначала подключите устройство и выполните следующую команду из корня проекта:

flutter test integration_test/app_test.dart

Или вы можете указать каталог для запуска всех интеграционных тестов:

flutter test integration_test

Эта команда запускает приложение и интеграционные тесты на целевом устройстве.

Чтобы начать тестирование в веб-браузере вначале скачайте https://chromedriver.chromium.org/downloads 

Затем создайте новый каталог с именем test_driver, содержащий новый файл с именем integration_test.dart:

```dart

Future<void> main() => integrationDriver();
```

Запустите chromedriver следующим образом:

chromedriver --port=4444

flutter drive \


