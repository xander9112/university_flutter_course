### 2. Unit-тесты: Use Cases

#### 2.1. Создать мок репозитория

Чтобы проверить use case отдельно от сети, настоящий репозиторий заменяют **моком** — объектом-заглушкой, поведение которого задаётся в тесте. Пакет `mocktail` создаёт моки без кодогенерации:

- `class MockX extends Mock implements X {}` — мок класса или интерфейса `X`;
- `when(() => mock.method()).thenAnswer((_) async => значение)` — что вернуть при вызове (для `Future` — `thenAnswer`, для обычного значения — `thenReturn`, для ошибки — `thenThrow`);
- `verify(() => mock.method()).called(1)` — проверить, что метод был вызван ровно один раз;
- `any()` / `any(named: 'имя')` — «любое значение аргумента».

Именно ради этого в Заданиях 15–16 все зависимости передавались через конструктор и описывались абстракциями: в тесте вместо них можно подставить мок.

Создайте файл `test/mocks/mock_movie_repository.dart`:

```dart
import 'package:mocktail/mocktail.dart';
import 'package:cine_track/features/movies/domain/repositories/movie_repository.dart';

class MockMovieRepository extends Mock implements MovieRepository {}
```

#### 2.2. Тест `GetPopularMovies`

Создайте файл `test/features/movies/domain/usecases/get_popular_movies_test.dart`:

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';
import 'package:cine_track/features/movies/domain/entities/movie.dart';
import 'package:cine_track/features/movies/domain/usecases/get_popular_movies.dart';
import '../../../../mocks/mock_movie_repository.dart';

void main() {
  late GetPopularMovies usecase;
  late MockMovieRepository mockRepository;

  setUp(() {
    mockRepository = MockMovieRepository();
    usecase = GetPopularMovies(mockRepository);
  });

  final tMovies = [
    const Movie(id: 1, title: 'Test Movie', releaseDate: '2024-01-01'),
  ];

  test('должен вернуть список фильмов из репозитория', () async {
    when(() => mockRepository.getPopularMovies(page: any(named: 'page')))
        .thenAnswer((_) async => tMovies);

    final result = await usecase();

    expect(result, equals(tMovies));
    verify(() => mockRepository.getPopularMovies(page: 1)).called(1);
    verifyNoMoreInteractions(mockRepository);
  });

  test('должен пробросить исключение при ошибке репозитория', () async {
    when(() => mockRepository.getPopularMovies(page: any(named: 'page')))
        .thenThrow(Exception('Сетевая ошибка'));

    expect(() => usecase(), throwsException);
  });
}
```

#### 2.3. Тест `MoviesBloc` с `bloc_test`

Функция `blocTest` из пакета `bloc_test` описывает тест блока в три шага: `build` создаёт блок (и настраивает моки), `act` отправляет события, `expect` перечисляет состояния, которые блок должен выдать по порядку. Сравнение состояний работает благодаря `==`, сгенерированному Freezed в Задании 17.

Создайте файл `test/features/movies/presentation/blocs/movies_bloc_test.dart`:

```dart
import 'package:bloc_test/bloc_test.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';
import 'package:cine_track/features/movies/domain/entities/movie.dart';
import 'package:cine_track/features/movies/domain/usecases/get_popular_movies.dart';
import 'package:cine_track/features/movies/domain/usecases/search_movies.dart';
import 'package:cine_track/features/movies/presentation/blocs/movies_bloc.dart';
import 'package:cine_track/features/movies/presentation/blocs/movies_event.dart';
import 'package:cine_track/features/movies/presentation/blocs/movies_state.dart';

class MockGetPopularMovies extends Mock implements GetPopularMovies {}
class MockSearchMovies extends Mock implements SearchMovies {}

void main() {
  late MoviesBloc bloc;
  late MockGetPopularMovies mockGetPopularMovies;
  late MockSearchMovies mockSearchMovies;

  final tMovies = [
    const Movie(id: 1, title: 'Inception', releaseDate: '2010-07-16'),
  ];

  setUp(() {
    mockGetPopularMovies = MockGetPopularMovies();
    mockSearchMovies = MockSearchMovies();
    bloc = MoviesBloc(
      getPopularMovies: mockGetPopularMovies,
      searchMovies: mockSearchMovies,
    );
  });

  tearDown(() => bloc.close());

  blocTest<MoviesBloc, MoviesState>(
    'LoadMovies: должен перейти в Loading → Loaded при успешной загрузке',
    build: () {
      when(() => mockGetPopularMovies()).thenAnswer((_) async => tMovies);
      return bloc;
    },
    act: (bloc) => bloc.add(const MoviesEvent.load()),
    expect: () => [
      const MoviesState.loading(),
      MoviesState.loaded(tMovies),
    ],
  );

  blocTest<MoviesBloc, MoviesState>(
    'LoadMovies: должен перейти в Error при сетевой ошибке',
    build: () {
      when(() => mockGetPopularMovies()).thenThrow(Exception('Нет сети'));
      return bloc;
    },
    act: (bloc) => bloc.add(const MoviesEvent.load()),
    expect: () => [
      const MoviesState.loading(),
      isA<MoviesError>(),
    ],
  );
}
```

### 3. Widget-тесты: компоненты UI

#### 3.1. Тест `MovieCard`

Создайте файл `test/features/movies/presentation/widgets/movie_card_test.dart`:

С Задания 12 `MovieCard` читает `FavoritesProvider` через `context.watch`, поэтому в тесте карточку нужно обернуть в провайдер. Подставим мок-провайдер, который говорит, что фильм не в избранном:

```dart
import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';
import 'package:provider/provider.dart';
import 'package:cine_track/features/favorites/presentation/providers/favorites_provider.dart';
import 'package:cine_track/features/movies/domain/entities/movie.dart';
import 'package:cine_track/features/movies/presentation/widgets/movie_card.dart';

class MockFavoritesProvider extends Mock implements FavoritesProvider {}

void main() {
  const tMovie = Movie(
    id: 1,
    title: 'Inception',
    voteAverage: 8.8,
    releaseDate: '2010-07-16',
  );

  late MockFavoritesProvider mockFavorites;

  setUp(() {
    mockFavorites = MockFavoritesProvider();
    when(() => mockFavorites.isFavorite(any())).thenReturn(false);
  });

  Future<void> pumpCard(WidgetTester tester) {
    return tester.pumpWidget(
      ChangeNotifierProvider<FavoritesProvider>.value(
        value: mockFavorites,
        child: const MaterialApp(
          home: Scaffold(body: MovieCard(movie: tMovie)),
        ),
      ),
    );
  }

  testWidgets('MovieCard отображает название фильма', (tester) async {
    await pumpCard(tester);
    expect(find.text('Inception'), findsOneWidget);
  });

  testWidgets('MovieCard отображает год выпуска', (tester) async {
    await pumpCard(tester);
    expect(find.textContaining('2010'), findsOneWidget);
  });

  testWidgets('MovieCard отображает рейтинг', (tester) async {
    await pumpCard(tester);
    expect(find.textContaining('8.8'), findsOneWidget);
  });

  testWidgets('Нажатие на сердце вызывает toggleFavorite', (tester) async {
    when(() => mockFavorites.toggleFavorite(tMovie)).thenAnswer((_) async {});
    await pumpCard(tester);

    await tester.tap(find.byIcon(Icons.favorite_border));

    verify(() => mockFavorites.toggleFavorite(tMovie)).called(1);
  });
}
```

### 4. Integration-тест: сценарий пользователя

Интеграционный тест запускает настоящее приложение целиком — с сетью, базой данных и DI. Поэтому `app.main()` вызывается **один раз**: повторный вызов `configureDependencies()` попытался бы зарегистрировать зависимости в GetIt второй раз и завершился бы ошибкой. Весь сценарий пользователя описывается в одном тесте.

Создайте директорию `integration_test/` и файл `integration_test/app_test.dart`:

```dart
import 'package:flutter/gestures.dart';
import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:integration_test/integration_test.dart';
import 'package:cine_track/main.dart' as app;
import 'package:cine_track/features/movies/presentation/screens/movie_detail_screen.dart';
import 'package:cine_track/features/movies/presentation/widgets/movie_card.dart';

void main() {
  IntegrationTestWidgetsFlutterBinding.ensureInitialized();

  testWidgets('Пользователь открывает детали фильма и добавляет его в избранное',
      (tester) async {
    await app.main();
    await tester.pumpAndSettle(const Duration(seconds: 5)); // ждём загрузки

    // Главный экран загрузился: на нём две ленты (Популярное и Все фильмы)
    expect(find.byType(ListView), findsWidgets);
    expect(find.byType(MovieCard), findsWidgets);

    // Нажимаем на первую карточку — открывается экран деталей.
    // У карточки есть onDoubleTap (Задание 9): одиночный тап засчитывается
    // только после таймаута двойного, а pumpAndSettle таймеры не ждёт.
    await tester.tap(find.byType(MovieCard).first);
    await tester.pump(kDoubleTapTimeout);
    await tester.pumpAndSettle();
    expect(find.byType(MovieDetailScreen), findsOneWidget);

    // Возвращаемся назад
    await tester.pageBack();
    await tester.pumpAndSettle();
    expect(find.byType(MovieDetailScreen), findsNothing);

    // Нажимаем иконку сердца на первой карточке — она становится заполненной.
    // Ищем иконку внутри карточки: Icons.favorite есть и на вкладке
    // «Избранное» в нижней панели, поэтому find.byIcon(Icons.favorite)
    // нашёл бы её даже без нажатия.
    final firstCard = find.byType(MovieCard).first;
    await tester.tap(
      find.descendant(of: firstCard, matching: find.byIcon(Icons.favorite_border)),
    );
    await tester.pump(kDoubleTapTimeout); // сердце лежит внутри той же карточки
    await tester.pumpAndSettle();
    expect(
      find.descendant(of: firstCard, matching: find.byIcon(Icons.favorite)),
      findsOneWidget,
    );

    // Переходим на вкладку «Избранное» в нижней панели
    await tester.tap(find.text('Избранное'));
    await tester.pumpAndSettle();

    // Фильм должен быть в списке
    expect(find.byType(MovieCard), findsAtLeastNWidgets(1));
  });
}
```

> Тест рассчитан на чистую установку: избранное хранится в SQLite (Задание 14), и если первый фильм уже был в избранном с прошлого запуска, нажатие на сердце уберёт его оттуда. Перед запуском удалите приложение с эмулятора.

> `pump(kDoubleTapTimeout)` нужен из-за двойного тапа из Задания 9: пока не прошли 300 мс, `GestureDetector` ждёт второго нажатия и не передаёт тап ни карточке, ни кнопке-сердцу внутри неё. Без этой паузы экран деталей не откроется и тест упадёт. В виджет-тестах `HomeScreen` действует то же правило.

### 5. Довести покрытие до 70%

Тесты из задач 2–3 проверяют лишь несколько классов — это примерно 8% строк слоёв domain и presentation. Чтобы выполнить последний критерий, допишите тесты по тем же образцам:

- **domain** — `SearchMovies`, `GetFavorites`, `ToggleFavorite` (обе ветки: добавить и убрать), `GetRatings`, `SetRating`, геттеры `Movie` (`year`, `rating`, `posterUrl` с данными и без);
- **`MoviesBloc`** — остальные события: `refresh` (в том числе с теми же фильмами — `Completer` из Задания 17 должен завершиться), `search` (успех, ошибка, пустой запрос → `initial`), `add`, `remove`, `shuffle`; начальное состояние задаётся параметром `seed` у `blocTest`;
- **провайдеры** — `FavoritesProvider` и `RatingsProvider` с моками use cases;
- **экраны** — `HomeScreen` (загрузка, ошибка и «Повторить», список, свайп с подтверждением), `SearchScreen`, `MovieDetailScreen` с диалогом оценки, `AddMovieScreen` (валидация формы), `MainScreen` (переключение вкладок).

Для экранов с блоком удобен `MockBloc` из `bloc_test` — состояния задаются через `whenListen`:

```dart
class MockMoviesBloc extends MockBloc<MoviesEvent, MoviesState>
    implements MoviesBloc {}

// в тесте
whenListen(bloc, const Stream<MoviesState>.empty(),
    initialState: const MoviesState.error('Нет сети'));
```

Аргументы своих типов в `any()` (например, `verify(() => bloc.add(any()))`) требуют заглушку: один раз вызовите `registerFallbackValue(const MoviesEvent.load())` в `setUpAll`.

`SearchScreen` берёт блок из GetIt (Задание 16). В тесте зарегистрируйте в `sl` блок с моками use cases вместо `configureDependencies()` и очистите контейнер после теста:

```dart
setUp(() => sl.registerFactory<MoviesBloc>(
      () => MoviesBloc(getPopularMovies: mockGetPopular, searchMovies: mockSearch),
    ));
tearDown(() => sl.reset());
```

Покрытие считается по `coverage/lcov.info` после `flutter test --coverage`. Сгенерированные файлы (`*.g.dart`, `*.freezed.dart`) и слой data в критерий не входят — исключите их из отчёта, например утилитой `lcov`:

```bash
lcov --remove coverage/lcov.info '*.g.dart' '*.freezed.dart' '*/data/*' '*/core/*' -o coverage/filtered.info
genhtml coverage/filtered.info -o coverage/html   # HTML-отчёт: coverage/html/index.html
```
