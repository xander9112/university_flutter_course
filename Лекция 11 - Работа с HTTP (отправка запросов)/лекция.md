# Лекция 11 - Работа с HTTP (отправка запросов)

Получение данных из Интернета необходимо для большинства приложений. К счастью, Dart и Flutter предоставляют такие инструменты, как пакет http, для такого типа работы.

Пакет http предоставляет самый простой способ получения данных из Интернета. Чтобы добавить пакет http в качестве зависимости, запустите flutter pub add:

flutter pub add http

И импортируйте пакет 

```dart
import 'package:http/http.dart' as http;
```

Кроме того, в файле AndroidManifest.xml в каталоге с проектом android добавьте разрешение на доступ в Интернет.

<!-- Required to fetch data from the internet. -->

<uses-permission android:name="android.permission.INTERNET" />

В примере ниже приведен код для получения альбома из сервиса https://jsonplaceholder.typicode.com используя метод http.get:

Future<http.Response> fetchAlbum() {

```dart
  return http.get(Uri.parse('https://jsonplaceholder.typicode.com/albums/1'));
}
```

Метод http.get() возвращает Future, который содержит Response.

Future — это основной класс Dart для работы с асинхронными операциями. Объект Future представляет потенциальное значение или ошибку, которые будут доступны в будущем. 

Класс http.Response содержит данные, полученные от успешного http-вызова.

Таким же образом можно и отправить данные с помощью метода http.post()

```dart
var response = await client.post(
      Uri.parse('https://example.com/whatsit/create'),
      body: {'name': 'doodle', 'color': 'blue'}
```

## Введение в JSON

JSON — текстовый формат обмена данными, основанный на JavaScript.

JSON-текст представляет собой (в закодированном виде) одну из двух структур:

Набор пар ключ: значение. В различных языках это реализовано как запись, структура, словарь, хеш-таблица, список с ключом или ассоциативный массив. Ключом может быть только строка (регистрозависимость не регулируется стандартом, это остаётся на усмотрение программного обеспечения. Как правило, регистр учитывается программами — имена с буквами в разных регистрах считаются разными, например[5]), значением — любая форма. Повторяющиеся имена ключей допустимы, но не рекомендуются стандартом; обработка таких ситуаций происходит на усмотрение программного обеспечения, возможные варианты — учитывать только первый такой ключ, учитывать только последний такой ключ, генерировать ошибку.

Упорядоченный набор значений. Во многих языках это реализовано как массив, вектор, список или последовательность.

В качестве значений в JSON могут быть использованы:

запись — это неупорядоченное множество пар ключ:значение, заключённое в фигурные скобки «{ }». Ключ описывается строкой, между ним и значением стоит символ «:». Пары ключ-значение отделяются друг от друга запятыми.

массив (одномерный) — это упорядоченное множество значений. Массив заключается в квадратные скобки «[ ]». Значения разделяются запятыми. Массив может быть пустым, то есть не содержать ни одного значения. Значения в пределах одного массива могут иметь разный тип.

число (целое или вещественное).

литералы true (логическое значение «истина»), false (логическое значение «ложь») и null.

строка — это упорядоченное множество из нуля или более символов юникода, заключённое в двойные кавычки. Символы могут быть указаны с использованием escape-последовательностей, начинающихся с обратной косой черты «\» (поддерживаются варианты \", \\, \/, \t, \n, \r, \f и \b), или записаны шестнадцатеричным кодом в кодировке Unicode в виде \uFFFF.

Следующий пример показывает JSON-представление данных об объекте, описывающем человека. В данных присутствуют строковые поля имени и фамилии, информация об адресе и массив, содержащий список телефонов. Как видно из примера, значение может представлять собой вложенную структуру.

```dart
{
   "firstName": "Иван",
   "lastName": "Иванов",
   "address": {
       "streetAddress": "Московское ш., 101, кв.101",
       "city": "Ленинград",
       "postalCode": 101101
   },
   "phoneNumbers": [
       "812 123-1234",
       "916 123-4567"
   ]
}
```

## Ручная сериализация JSON. Создание модели, отображение данных.

И так мы сделали запрос в сервис https://jsonplaceholder.typicode.com для получения альбома.

Future<http.Response> fetchAlbum() {

```dart
  return http.get(Uri.parse('https://jsonplaceholder.typicode.com/albums/1'));
}
```

Сервис нам отдает ответ в формате JSON:

```dart
{
  "userId": 1,
  "id": 1,
  "title": "quidem molestiae enim"
}
```

Для начала создадим класс содержащий данные из этого запроса.

Он включает конструктор фабрики, который создает альбом из JSON.

```dart
class Album {
  final int userId;
  final int id;
  final String title;
  const Album({
    required this.userId,
    required this.id,
    required this.title,
  });
  factory Album.fromJson(Map<String, dynamic> json) {
    return Album(
      userId: json['userId'],
      id: json['id'],
      title: json['title'],
    );
  }
}
```

Далее нам нужно сконвертировать http.Response в Album

Для этого нам нужно:

Преобразуйте тело ответа в  JSON в Map с помощью пакета dart:convert.

Если сервер возвращает ответ OK с кодом состояния 200, преобразуем  Map в Album с помощью фабричного метода fromJson().

Если сервер не возвращает ответ OK с кодом состояния 200, создадим исключение. 

Future<Album> fetchAlbum() async {

```dart
  final response = await http
      .get(Uri.parse('https://jsonplaceholder.typicode.com/albums/1'));
  if (response.statusCode == 200) {
    // If the server did return a 200 OK response,
    // then parse the JSON.
    return Album.fromJson(jsonDecode(response.body));
  } else {
    // If the server did not return a 200 OK response,
    // then throw an exception.
    throw Exception('Failed to load album');
  }
}
```

Теперь у нас есть функция которая получает экземпляр класса Album из сервиса.

Аналогичным образом мы можем сконвертировать наш объект обратно в JSON

Для этого добавим в класс Album функцию toJson()

```dart
Map<String, dynamic> toJson() => {'userId': userId, 'id': id, 'title': title};
```

Далее используя jsonEncode(album.toJson()) мы можем сериализовать в строку формата JSON, чтобы отправить на удаленный сервер.

Future<void> sendAlbum(Album album) async {

```dart
  final response = await http
      .post(Uri.parse('https://jsonplaceholder.typicode.com/albums/1'), body: jsonEncode(album.toJson()));
  if (response.statusCode == 200) {
      return;
  } else {
    // If the server did not return a 200 OK response,
    // then throw an exception.
    throw Exception('Failed to send album');
  }
}
```

Пакет http может автоматически сериализовать Map<String,dynamic> поэтому вызов jsonEncode в данном случае необязателен.

## Автогенерируемая сериализация JSON

Автогенеруриемая сериализация JSON означает, что внешняя библиотека генерирует шаблон кода для вас. После первоначальной настройки вы запускаете средство просмотра файлов, которое генерирует код из классов вашей модели. Например, такими библиотеками являются json_serializable и build_value.

Этот подход хорошо масштабируется для более крупного проекта. Рукописный шаблон не требуется, а опечатки при доступе к полям JSON обнаруживаются во время компиляции. Поскольку код сериализации больше не пишется вручную и не поддерживается вручную, вы сводите к минимуму риск возникновения исключений сериализации JSON во время выполнения. Недостатком генерации кода является то, что она требует некоторой первоначальной настройки. Кроме того, сгенерированные исходные файлы могут создавать визуальный беспорядок в навигаторе проекта.

Возможно, вы захотите использовать сгенерированный код для сериализации JSON, если у вас есть средний или крупный проект. 

Хотя доступны и другие библиотеки, в этом уроке используется json_serializable, автоматический генератор исходного кода, который генерирует код для сериализации классов.

Чтобы включить json_serializable в свой проект, вам понадобится одна обычная зависимость и две зависимости разработчика. Короче говоря, зависимости разработки — это зависимости, которые не включены в исходный код нашего приложения — они используются только в среде разработки.

flutter pub add json_annotation dev:build_runner dev:json_serializable

Запустите flutter pub get в корневой папке вашего проекта (или щелкните Packages get в вашем редакторе), чтобы сделать эти новые зависимости доступными в вашем проекте.

Ниже показано, как преобразовать класс Album в класс json_serializable. 

```dart
import 'package:json_annotation/json_annotation.dart';
/// This allows the `Album` class to access private members in
```

/// the generated file. The value for this is *.g.dart, where

/// the star denotes the source file name.

part album.g.dart';

```dart
/// An annotation for the code generator to know that this class needs the
```

/// JSON serialization logic to be generated.

@JsonSerializable()

```dart
class Album {
  final int userId;
  final int id;
  final String title;
  const Album({
    required this.userId,
    required this.id,
    required this.title,
  });
  /// A necessary factory constructor for creating a new User instance
  /// from a map. Pass the map to the generated `_$UserFromJson()` constructor.
  /// The constructor is named after the source class, in this case, User.
  factory Album.fromJson(Map<String, dynamic> json) => _$AlbumFromJson(json);
  /// `toJson` is the convention for a class to declare support for serialization
  /// to JSON. The implementation simply calls the private, generated
  /// helper method `_$AlbumToJson`.
  Map<String, dynamic> toJson() => _$AlbumToJson(this);
}
```

При необходимости также легко настроить стратегию именования. Например, если API возвращает объекты с snake_case , и вы хотите использовать в своих моделях lowerCamelCase, вы можете использовать аннотацию @JsonKey с параметром имени:

 @JsonKey(name: 'user_id')

```dart
 final int userId;
```

В нашем случае в этом нет необходимости, поэтому оставим первый вариант.

Иногда необходимо проверять и защищать данные на клиенте. Для этого используют другие аннотации @JsonKey, которые включают:

/// Tell json_serializable to use "defaultValue" if the JSON doesn't

/// contain this key or if the value is `null`.

@JsonKey(defaultValue: false)

```dart
final bool isAdult;
```

/// When `true` tell json_serializable that JSON must contain the key, 

/// If the key doesn't exist, an exception is thrown.

@JsonKey(required: true)

```dart
final String id;
```

/// When `true` tell json_serializable that generated code should 

/// ignore this field completely. 

@JsonKey(ignore: true)

```dart
final String verificationCode;
```
