# Задание 16 — Dependency Injection: подключение GetIt к CineTrack

## Контекст

Продолжаем разработку **CineTrack**. В Задании 15 все зависимости собираются вручную в `lib/app_dependencies.dart`: каждый вызов `createMoviesBloc()` заново создаёт репозиторий и HTTP-клиент, а любая новая зависимость требует правки этого файла. В этом задании вы подключаете **GetIt** + **Injectable**: классы помечаются аннотациями, а код регистрации генерируется автоматически.

---

## Задача 1. Добавить пакеты в pubspec.yaml

Откройте `pubspec.yaml` и добавьте зависимости:

```yaml
dependencies:
  flutter:
    sdk: flutter
  # ... существующие зависимости ...
  get_it: ^7.7.0
  injectable: ^2.4.0

dev_dependencies:
  flutter_test:
    sdk: flutter
  # ... существующие dev-зависимости ...
  injectable_generator: ^2.4.0
  build_runner: ^2.4.0
```

Выполните `flutter pub get`.

`build_runner` — инструмент кодогенерации: он читает аннотации в вашем коде и создаёт по ним `.dart`-файлы. Подробно кодогенерацию разберём в Лекции 17, а в этом задании достаточно одной команды из Задачи 7.

## Задача 2. Создать injection.dart и вызвать configureDependencies() в main()

Создайте файл `lib/core/di/injection.dart`:

```dart
import 'package:get_it/get_it.dart';
import 'package:injectable/injectable.dart';
import 'injection.config.dart'; // будет сгенерирован

final sl = GetIt.instance;

@InjectableInit(
  initializerName: 'init',
  preferRelativeImports: true,
  asExtension: true,
)
Future<void> configureDependencies() async => sl.init();
```

Обновите `main()` в `lib/main.dart`:

```dart
import 'core/di/injection.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  if (kIsWeb) databaseFactory = databaseFactoryFfiWeb; // SQLite в браузере (Задание 14)
  await configureDependencies(); // регистрируем все зависимости до runApp
  runApp(/* MultiProvider с MyApp — см. Задачу 6 */);
}
```

## Задача 3. Зарегистрировать внешние зависимости через @module

`http.Client` — класс из чужого пакета, поставить на него аннотацию нельзя. Такие зависимости регистрируются в модуле. Создайте файл `lib/core/di/app_module.dart`:

```dart
import 'package:http/http.dart' as http;
import 'package:injectable/injectable.dart';

@module
abstract class AppModule {
  @lazySingleton
  http.Client get httpClient => http.Client();
}
```

`@lazySingleton` означает: объект создаётся при первом запросе и дальше переиспользуется. Теперь во всём приложении будет один `http.Client`.

## Задача 4. Аннотировать data-слой

Источники данных и репозитории регистрируются **под типом абстракции** (`as:`) — остальной код запрашивает `MovieRepository`, не зная о конкретной реализации:

```dart
// lib/features/movies/data/datasources/movie_remote_datasource.dart
@LazySingleton(as: MovieRemoteDataSource)
class MovieRemoteDataSourceImpl implements MovieRemoteDataSource {
  final http.Client _client;
  MovieRemoteDataSourceImpl(this._client); // http.Client возьмётся из AppModule

  // ... реализация из Задания 15 без изменений
}
```

```dart
// lib/features/movies/data/datasources/movie_local_datasource.dart
@LazySingleton(as: MovieLocalDataSource)
class MovieLocalDataSourceImpl implements MovieLocalDataSource {
  // ... реализация из Задания 15 без изменений
}
```

```dart
// lib/features/movies/data/repositories/movie_repository_impl.dart
@LazySingleton(as: MovieRepository)
class MovieRepositoryImpl implements MovieRepository {
  final MovieRemoteDataSource remoteDataSource;
  final MovieLocalDataSource localDataSource;

  const MovieRepositoryImpl({
    required this.remoteDataSource,
    required this.localDataSource,
  });

  // ... реализация из Задания 15 без изменений
}
```

Injectable умеет заполнять и позиционные, и именованные параметры конструктора — менять сигнатуры из Задания 15 не нужно.

Аналогично пометьте `@LazySingleton(as: FavoritesRepository)` класс `FavoritesRepositoryImpl` и `@LazySingleton(as: RatingsRepository)` класс `RatingsRepositoryImpl`.

Не забудьте в каждом файле добавить `import 'package:injectable/injectable.dart';`.

## Задача 5. Аннотировать use cases, BLoC и провайдер

Use cases не хранят состояния, поэтому их можно сделать синглтонами:

```dart
// lib/features/movies/domain/usecases/get_popular_movies.dart
@lazySingleton
class GetPopularMovies {
  final MovieRepository repository;
  const GetPopularMovies(this.repository);

  Future<List<Movie>> call({int page = 1}) => repository.getPopularMovies(page: page);
}
```

Так же пометьте `@lazySingleton` классы `SearchMovies`, `GetFavorites`, `ToggleFavorite`, `GetRatings` и `SetRating`.

`MoviesBloc`, `FavoritesProvider` и `RatingsProvider` хранят состояние экрана и закрываются вместе с ним, поэтому регистрируются как **factory** (`@injectable`) — при каждом запросе создаётся новый экземпляр:

```dart
// lib/features/movies/presentation/blocs/movies_bloc.dart
@injectable // factory: новый экземпляр при каждом BlocProvider
class MoviesBloc extends Bloc<MoviesEvent, MoviesState> {
  final GetPopularMovies _getPopularMovies;
  final SearchMovies _searchMovies;

  MoviesBloc({
    required this._getPopularMovies,
    required this._searchMovies,
  }) : super(MoviesInitial()) {
    // ... обработчики событий из Задания 15 без изменений
  }
}
```

```dart
// lib/features/favorites/presentation/providers/favorites_provider.dart
@injectable
class FavoritesProvider extends ChangeNotifier {
  // ... без изменений
}
```

Так же пометьте `@injectable` класс `RatingsProvider`.

Именно поэтому в Задании 13 у `SearchScreen` был свой экземпляр `MoviesBloc`: factory-регистрация даёт каждому `BlocProvider` собственный блок.

## Задача 6. Заменить ручное создание на sl<T>()

До (Задание 15):

```dart
// main.dart
BlocProvider(create: (_) => createMoviesBloc()..add(LoadMovies())),
ChangeNotifierProvider(create: (_) => createFavoritesProvider()),
ChangeNotifierProvider(create: (_) => createRatingsProvider()),

// search_screen.dart
BlocProvider(create: (_) => createMoviesBloc(), child: const _SearchView())
```

После:

```dart
// main.dart
runApp(
  MultiProvider(
    providers: [
      BlocProvider(create: (_) => sl<MoviesBloc>()..add(LoadMovies())),
      ChangeNotifierProvider(create: (_) => sl<FavoritesProvider>()),
      ChangeNotifierProvider(create: (_) => sl<RatingsProvider>()),
      ChangeNotifierProvider(create: (_) => ThemeProvider()),
    ],
    child: const MyApp(),
  ),
);

// search_screen.dart
BlocProvider(create: (_) => sl<MoviesBloc>(), child: const _SearchView())
```

Удалите файл `lib/app_dependencies.dart` — он больше не нужен.

## Задача 7. Запустить build_runner и проверить работу

```bash
# Генерируем injection.config.dart
dart run build_runner build --delete-conflicting-outputs
```

После генерации в `lib/core/di/` появится файл `injection.config.dart`. Откройте его и убедитесь, что в нём зарегистрированы все ваши классы. Если вы добавили новую аннотацию — команду нужно запустить снова.

Запустите приложение (ключ TMDB передаётся так же, как в Задании 11):

```bash
flutter run --dart-define=TMDB_API_KEY=ваш_ключ
```

Проверьте:
- Приложение запускается без ошибок
- Список фильмов загружается
- Поиск работает и не меняет список на главном экране
- Избранное и личные оценки сохраняются
