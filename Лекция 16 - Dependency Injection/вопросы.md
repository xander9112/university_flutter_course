# Вопросы — Лекция 16: Dependency Injection

1. В чём главное отличие `registerSingleton` от `registerFactory` в GetIt?

   a) `registerSingleton` создаёт объект лениво, а `registerFactory` — сразу
   b) ✓ `registerSingleton` возвращает один и тот же объект, а `registerFactory` создаёт новый при каждом вызове
   c) `registerFactory` может регистрировать только абстрактные классы
   d) Между ними нет разницы, оба создают один экземпляр

2. Когда `registerLazySingleton` создаёт объект?

   a) Сразу при вызове `registerLazySingleton`
   b) При запуске функции `configureDependencies()`
   c) ✓ При первом обращении к объекту через `sl<T>()`
   d) При каждом вызове `sl<T>()`

3. Для чего используется аннотация `@module` в пакете injectable?

   a) Для группировки нескольких BLoC-классов в один модуль
   b) Для обозначения главного файла зависимостей
   c) ✓ Для регистрации внешних зависимостей (Dio, SharedPreferences), которые мы не можем аннотировать напрямую
   d) Для создания тестовых замен реальных зависимостей

4. Как получить зарегистрированный объект через GetIt?

   a) `GetIt.get<T>()`
   b) `inject<T>()`
   c) `GetIt.resolve<T>()`
   d) ✓ `sl<T>()` (где `sl` — это `GetIt.instance`)

5. Почему DI улучшает тестируемость кода?

   a) DI автоматически генерирует mock-объекты
   b) DI убирает необходимость в написании тестов
   c) ✓ Зависимости передаются снаружи, поэтому в тестах легко подставить mock вместо реальной реализации
   d) DI делает классы независимыми от сети, поэтому тесты быстрее

6. Что генерирует пакет injectable при запуске `build_runner`?

   a) Файлы с mock-объектами для тестирования
   b) Документацию по всем зарегистрированным зависимостям
   c) ✓ Файл `injection.config.dart` с кодом регистрации всех аннотированных зависимостей в GetIt
   d) Абстрактные классы для каждой зарегистрированной зависимости

7. В чём разница между DI (Dependency Injection) и ручным созданием зависимостей внутри класса?

   a) При DI объекты создаются быстрее
   b) При ручном создании зависимости видны в конструкторе
   c) При DI используется больше памяти
   d) ✓ При DI зависимости передаются снаружи, что убирает жёсткую связь и позволяет подменять реализации

8. Для чего используется аннотация `@injectable` на классе BLoC?

   a) Для обозначения того, что BLoC является синглтоном
   b) Для регистрации BLoC как абстрактного типа
   c) ✓ Для регистрации BLoC как factory — при каждом `sl<MoviesBloc>()` создаётся новый экземпляр
   d) Для автоматического закрытия BLoC при удалении из дерева виджетов
