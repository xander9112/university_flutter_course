# Лекция 16 — Dependency Injection: GetIt и Injectable

## 1. Проблема без DI

Когда зависимости создаются прямо внутри классов, возникает **жёсткая связь** (tight coupling). Класс сам знает, как создать то, что ему нужно — это делает его тяжёлым для тестирования и замены реализаций.

```dart
// ПЛОХО: жёсткая связь
class MoviesBloc extends Bloc<MoviesEvent, MoviesState> {
  // Блок сам создаёт сервис — мы не можем подменить его в тестах
  final MovieApiService _service = MovieApiService();

  MoviesBloc() : super(MoviesInitial()) {
    on<LoadMovies>(_onLoadMovies);
  }
}

// В main.dart — вручную прокидываем зависимости вниз по дереву
void main() {
  runApp(
    BlocProvider(
      create: (_) => MoviesBloc(),  // зависимости "зашиты" внутри
      child: MyApp(),
    ),
  );
}
```

**Последствия:**
- Нельзя подменить `MovieApiService` на mock в тестах
- При изменении конструктора `MovieApiService` нужно менять все места создания
- Сложно переиспользовать классы с разными конфигурациями

**Решение** — передавать зависимости снаружи (Dependency Injection):

```dart
// ХОРОШО: зависимость передаётся через конструктор
class MoviesBloc extends Bloc<MoviesEvent, MoviesState> {
  final MovieRepository _repository;

  MoviesBloc({required MovieRepository repository})
      : _repository = repository,
        super(MoviesInitial()) {
    on<LoadMovies>(_onLoadMovies);
  }
}
```

Теперь в тестах можно передать mock, а в продакшне — реальную реализацию.

## 2. Service Locator

**Service Locator** — паттерн, при котором есть единый глобальный реестр объектов. Любой класс может запросить нужную зависимость из этого реестра по типу.

```
Приложение
├── ServiceLocator (глобальный реестр)
│   ├── http.Client → Client
│   ├── MovieRepository → MovieRepositoryImpl
│   └── MoviesBloc → MoviesBloc
└── Виджеты запрашивают объекты: sl<MoviesBloc>()
```

**Плюсы:**
- Централизованное управление зависимостями
- Легко переключать реализации (продакшн / тест / staging)

**Минусы:**
- Зависимости неявные (не видны в конструкторе)
- Риск использовать объект до его регистрации

В Flutter самый популярный пакет для Service Locator — **GetIt**.

## 3. Пакет get_it

### Установка

```yaml
# pubspec.yaml
dependencies:
  get_it: ^9.3.0
```

### Создание экземпляра

```dart
import 'package:get_it/get_it.dart';

// Глобальный alias — принято называть sl (service locator)
final sl = GetIt.instance;
```

### Виды регистрации

#### `registerSingleton<T>` — один объект на всё приложение

Объект создаётся **сразу** при регистрации и живёт до конца работы приложения.

```dart
// Создаётся немедленно при вызове registerSingleton
sl.registerSingleton<http.Client>(http.Client());
```

#### `registerLazySingleton<T>` — создаётся при первом обращении

Объект создаётся только тогда, когда кто-то первый раз вызовет `sl<T>()`. Экономит ресурсы при старте.

```dart
// Функция-фабрика вызывается лишь один раз — при первом sl<MovieRepository>()
sl.registerLazySingleton<MovieRepository>(
  () => MovieRepositoryImpl(
    remoteDataSource: sl<MovieRemoteDataSource>(),
    localDataSource: sl<MovieLocalDataSource>(),
  ),
);
```

#### `registerFactory<T>` — новый объект при каждом вызове

Каждый вызов `sl<T>()` создаёт **новый** экземпляр. Подходит для BLoC, ViewModel — объектов с состоянием.

```dart
// Каждый раз новый BLoC
sl.registerFactory<MoviesBloc>(
  () => MoviesBloc(
    getPopularMovies: sl<GetPopularMovies>(),
    searchMovies: sl<SearchMovies>(),
  ),
);
```

### Получение зависимости

```dart
// Где угодно в коде:
final client = sl<http.Client>();
final bloc = sl<MoviesBloc>();

// Или через call:
final repo = sl<MovieRepository>();
```

### Порядок регистрации

Зависимости нужно регистрировать **от базовых к зависимым**:

```dart
// lib/core/di/injection.dart

final sl = GetIt.instance;

Future<void> configureDependencies() async {
  // 1. Внешние зависимости (нет зависимостей от наших классов)
  sl.registerLazySingleton<http.Client>(() => http.Client());

  // 2. Data sources (зависят от http.Client)
  sl.registerLazySingleton<MovieRemoteDataSource>(
    () => MovieRemoteDataSourceImpl(sl<http.Client>()),
  );
  sl.registerLazySingleton<MovieLocalDataSource>(
    () => MovieLocalDataSourceImpl(),
  );

  // 3. Repository (зависит от data sources)
  sl.registerLazySingleton<MovieRepository>(
    () => MovieRepositoryImpl(
      remoteDataSource: sl<MovieRemoteDataSource>(),
      localDataSource: sl<MovieLocalDataSource>(),
    ),
  );

  // 4. Use cases (зависят от repository)
  sl.registerLazySingleton(() => GetPopularMovies(sl<MovieRepository>()));
  sl.registerLazySingleton(() => SearchMovies(sl<MovieRepository>()));

  // 5. BLoC (зависит от use cases) — factory, т.к. имеет состояние
  sl.registerFactory<MoviesBloc>(
    () => MoviesBloc(
      getPopularMovies: sl<GetPopularMovies>(),
      searchMovies: sl<SearchMovies>(),
    ),
  );
}
```

```dart
// main.dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await configureDependencies(); // сначала регистрируем
  runApp(const MyApp());
}
```

## 4. Пакет injectable — кодогенерация для GetIt

Писать `injection.dart` вручную утомительно и чревато ошибками. Пакет **injectable** генерирует этот файл автоматически на основе аннотаций.

### Установка

```yaml
# pubspec.yaml
dependencies:
  get_it: ^9.3.0
  injectable: ^3.0.0

dev_dependencies:
  injectable_generator: ^3.1.3
  build_runner: ^2.16.1
```

### Аннотации

```dart
// @injectable — новый экземпляр при каждом запросе (как registerFactory)
@injectable
class MoviesBloc extends Bloc<MoviesEvent, MoviesState> {
  // injectable заполняет и позиционные, и именованные параметры конструктора
  MoviesBloc({
    required GetPopularMovies getPopularMovies,
    required SearchMovies searchMovies,
  })  : _getPopularMovies = getPopularMovies,
        _searchMovies = searchMovies,
        super(MoviesInitial());

  final GetPopularMovies _getPopularMovies;
  final SearchMovies _searchMovies;
}

// @singleton — один экземпляр, создаётся сразу (как registerSingleton)
@singleton
class AnalyticsService {
  void logEvent(String name) { /* ... */ }
}

// @lazySingleton — один экземпляр, создаётся при первом обращении
@lazySingleton
class MovieRepositoryImpl implements MovieRepository {
  MovieRepositoryImpl(this._remote, this._local);

  final MovieRemoteDataSource _remote;
  final MovieLocalDataSource _local;
}
```

### Регистрация абстракций

Если класс реализует интерфейс, нужно указать это явно:

```dart
@LazySingleton(as: MovieRepository)
class MovieRepositoryImpl implements MovieRepository {
  // ...
}
```

### @module — регистрация внешних зависимостей

Для сторонних классов (http.Client, SharedPreferences, Database), которые мы не можем аннотировать, используется `@module`:

```dart
@module
abstract class AppModule {
  // lazySingleton — клиент создаётся один раз при первом обращении
  @lazySingleton
  http.Client get httpClient => http.Client();

  // Async-зависимость (SharedPreferences требует await)
  @preResolve
  @lazySingleton
  Future<SharedPreferences> get prefs => SharedPreferences.getInstance();
}
```

### Генерация кода

```dart
// lib/core/di/injection.dart

import 'package:get_it/get_it.dart';
import 'package:injectable/injectable.dart';
import 'injection.config.dart'; // будет сгенерирован

final sl = GetIt.instance;

@InjectableInit(
  initializerName: 'init',    // имя генерируемой функции
  preferRelativeImports: true,
  asExtension: true,
)
Future<void> configureDependencies() async => sl.init();
```

Запускаем генератор:

```bash
dart run build_runner build --delete-conflicting-outputs
```

После этого появится файл `injection.config.dart` с готовой регистрацией всех зависимостей. `build_runner` — общий инструмент кодогенерации в Dart; подробно о нём и о других генераторах (Freezed, json_serializable, Retrofit) — в Лекции 17.

## 5. Интеграция с Clean Architecture

Вспомним структуру из Лекции 15:

```
lib/
├── features/
│   └── movies/
│       ├── data/
│       │   ├── datasources/
│       │   │   ├── movie_remote_datasource.dart    @LazySingleton(as: MovieRemoteDataSource)
│       │   │   └── movie_local_datasource.dart     @LazySingleton(as: MovieLocalDataSource)
│       │   ├── repositories/
│       │   │   └── movie_repository_impl.dart      @LazySingleton(as: MovieRepository)
│       │   └── models/
│       ├── domain/
│       │   ├── repositories/
│       │   │   └── movie_repository.dart           (абстракция)
│       │   └── usecases/
│       │       ├── get_popular_movies.dart         @lazySingleton
│       │       └── search_movies.dart              @lazySingleton
│       └── presentation/
│           └── blocs/
│               └── movies_bloc.dart                @injectable
└── core/
    └── di/
        ├── injection.dart
        └── injection.config.dart    (генерируется)
```

### Пример полной цепочки для фичи Movies

```dart
// domain/repositories/movie_repository.dart
// Интерфейс — НЕ аннотируем, это просто контракт
abstract class MovieRepository {
  Future<List<Movie>> getPopularMovies({int page = 1});
  Future<List<Movie>> searchMovies(String query);
}

// data/repositories/movie_repository_impl.dart
@LazySingleton(as: MovieRepository)  // говорим injectable: это реализация MovieRepository
class MovieRepositoryImpl implements MovieRepository {
  const MovieRepositoryImpl({
    required this.remoteDataSource,
    required this.localDataSource,
  });

  final MovieRemoteDataSource remoteDataSource;
  final MovieLocalDataSource localDataSource;

  @override
  Future<List<Movie>> getPopularMovies({int page = 1}) async {
    try {
      final dtos = await remoteDataSource.getPopularMovies(page: page);
      await localDataSource.cacheMovies(dtos);
      return dtos.map((dto) => dto.toEntity()).toList();
    } catch (_) {
      final cached = await localDataSource.getCachedMovies();
      return cached.map((dto) => dto.toEntity()).toList();
    }
  }

  // searchMovies — аналогично
}

// domain/usecases/get_popular_movies.dart
@lazySingleton
class GetPopularMovies {
  const GetPopularMovies(this.repository);
  final MovieRepository repository;

  Future<List<Movie>> call({int page = 1}) => repository.getPopularMovies(page: page);
}

// presentation/blocs/movies_bloc.dart
@injectable  // новый BLoC при каждом запросе
class MoviesBloc extends Bloc<MoviesEvent, MoviesState> {
  MoviesBloc({
    required GetPopularMovies getPopularMovies,
    required SearchMovies searchMovies,
  })  : _getPopularMovies = getPopularMovies,
        _searchMovies = searchMovies,
        super(MoviesInitial()) {
    on<LoadMovies>(_onLoadMovies);
    on<SearchMoviesRequested>(_onSearchMoviesRequested);
    // ... остальные события
  }

  final GetPopularMovies _getPopularMovies;
  final SearchMovies _searchMovies;
}
```

Ни один из этих классов не обращается к `sl` — зависимости приходят через конструктор. Связывает их сгенерированный `injection.config.dart`.

## 6. Dependency Injection vs Service Locator

| Аспект | Dependency Injection | Service Locator |
|--------|---------------------|-----------------|
| Зависимости видны в конструкторе | Да | Нет |
| Класс знает о реестре | Нет | Да (вызывает `sl<T>()`) |
| Тестируемость | Очень высокая | Высокая |
| Удобство | Требует настройки | Проще в небольших проектах |
| Типичный пример во Flutter | Provider, Riverpod | GetIt |

**Рекомендация:** GetIt с Injectable — хороший компромисс для Flutter. Конструкторы остаются чистыми (injectable генерирует DI-код), а `sl<T>()` используется только в `BlocProvider` / точках входа.

## 7. Тестирование с DI

Один из главных плюсов DI — **лёгкая подмена реализаций** в тестах.

```dart
// test/features/movies/presentation/bloc/movies_bloc_test.dart
void main() {
  late MoviesBloc bloc;
  late MockGetPopularMovies mockGetPopularMovies;
  late MockSearchMovies mockSearchMovies;

  setUp(() {
    mockGetPopularMovies = MockGetPopularMovies();
    mockSearchMovies = MockSearchMovies();

    // Перерегистрируем в тестовом окружении
    sl.registerSingleton<GetPopularMovies>(mockGetPopularMovies);
    sl.registerSingleton<SearchMovies>(mockSearchMovies);

    // Или напрямую через конструктор — ещё чище:
    bloc = MoviesBloc(
      getPopularMovies: mockGetPopularMovies,
      searchMovies: mockSearchMovies,
    );
  });

  tearDown(() {
    bloc.close();
    sl.reset(); // сбрасываем регистрации после каждого теста
  });

  group('LoadMovies', () {
    final tMovies = [
      const Movie(id: 1, title: 'Inception', releaseDate: '2010-07-16'),
    ];

    blocTest<MoviesBloc, MoviesState>(
      'emits [Loading, Loaded] when successful',
      build: () {
        when(() => mockGetPopularMovies()).thenAnswer((_) async => tMovies);
        return bloc;
      },
      act: (b) => b.add(LoadMovies()),
      expect: () => [
        isA<MoviesLoading>(),
        isA<MoviesLoaded>().having((s) => s.movies, 'movies', tMovies),
      ],
    );
  });
}
```

Благодаря DI:
- `MoviesBloc` не знает, откуда берутся данные
- В тесте легко передать `MockGetPopularMovies`
- Тест не делает реальных HTTP-запросов
