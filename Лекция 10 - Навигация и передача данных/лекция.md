# Лекция 10 - Навигация и передача данных

## Простая навигация

Навигация является важной частью любого мобильного приложения, и Flutter предоставляет богатый набор виджетов и API для реализации навигации в вашем приложении.

Основные понятия навигации

Давайте в начале рассмотрим некоторые основные концепции навигации во Flutter.

Navigator

Navigator — это виджет, который управляет стеком экранов в вашем приложении Flutter. Он предоставляет методы для добавления нового экрана в стек, удаления верхнего экрана из стека или замены текущего экрана новым экраном.

BuildContext

BuildContext — это объект, который представляет местоположение виджета в дереве виджетов. Он обычно используется во Flutter для получения ссылки на ближайший виджет навигатора, который можно использовать для выполнения навигационных операций.

Screen или route

В Flutter screen или route представляют собой отдельную страницу или экран в вашем приложении. Каждому экрану обычно соответствует отдельный виджет, который определяет пользовательский интерфейс для этого экрана.

Именованные маршруты

Именованные маршруты — это способ присвоить каждому экрану в вашем приложении уникальный идентификатор. Вместо перехода к экрану, помещая его в стек, вы можете перейти к экрану, используя его уникальный идентификатор. Такой подход облегчает навигацию между экранами и может упростить код для управления навигацией внутри вашего приложения.

Передача данных между экранами

Приложениям часто приходится передавать данные между экранами. В Flutter вы можете передавать данные на новый экран при переходе к нему, передавая аргументы виджету Navigator. Затем вы можете получить доступ к этим данным в виджете нового экрана, чтобы заполнить пользовательский интерфейс.

В целом, навигация в Flutter включает в себя управление стеком экранов или маршрутов с помощью виджета Navigator и объектов BuildContext. Именованные маршруты и передача данных между экранами — это дополнительные концепции, которые могут помочь вам создать более сложную и гибкую навигацию в вашем приложении.

Виджет Navigator

Виджет Navigator является фундаментальным компонентом навигации во Flutter. Он управляет стеком экранов или маршрутов и предоставляет методы для добавления новых экранов в стек, удаления экранов из стека и замены текущего экрана новым экраном.

Когда вы помещаете новый экран в стек, новый экран добавляется в верхнюю часть стека, а предыдущий экран опускается на один уровень ниже. Это создает набор экранов, по которым можно перемещаться с помощью кнопки «Назад» на устройствах Android или жеста «свайп» на устройствах iOS.

Чтобы использовать виджет Navigator, вам обычно необходимо получить ссылку на него с помощью объекта BuildContext. Это делается путем передачи объекта BuildContext обратному вызову onPressed виджета или аналогичному обработчику событий. Как только у вас появится ссылка на навигатор, вы можете использовать его методы для перемещения, всплывания или замены экранов в стеке.

Вот некоторые из наиболее распространенных методов работы виджета Navigator:

```dart
push: помещает новый экран в стек.
pop: удаляет текущий экран из стека и возвращает к предыдущему экрану.
popUntil: удаляет все экраны из стека до тех пор, пока не будет выполнено определенное условие.
pushReplacement: заменяет текущий экран новым экраном.
pushNamed: помещает именованный маршрут в стек.
```

Самая простая форма навигации в Flutter — это использование виджета Navigator для перемещения экранов в стек и из него. Вот пример:

Navigator.push(

```dart
  context,
  MaterialPageRoute(builder: (context) => SecondScreen()),
);
```

В этом примере мы помещаем новый экран в стек, используя метод Navigator.push. Мы передаем BuildContext для текущего экрана, а также MaterialPageRoute, который определяет новый экран, который будет помещен в стек. В этом случае новый экран является экземпляром SecondScreen.

Чтобы вернуться к предыдущему экрану, мы можем использовать метод Navigator.pop:

Navigator.pop(context);

Это выводит текущий экран из стека и возвращает к предыдущему экрану.

## Навигация по имени

Хотя базовый подход к навигации прекрасно работает для небольших приложений, он может быстро стать громоздким по мере усложнения приложения. Лучшим подходом является использование именованных маршрутов, которые присваивают каждому экрану в приложении уникальный идентификатор. Вот пример:

MaterialApp(

```dart
  routes: {
    '/': (context) => HomeScreen(),
    '/second': (context) => SecondScreen(),
  },
);
```

В этом примере мы определяем два именованных маршрута: ‘/‘, который сопоставляется виджету HomeScreen, и ‘/second‘, который сопоставляется виджету SecondScreen. Затем мы можем использовать метод Navigator.pushNamed для перехода к экрану, используя его именованный маршрут:

Navigator.pushNamed(context, '/second');

Это более структурированный подход к навигации, поскольку он позволяет нам легко добавлять новые экраны в приложение и переходить к ним, используя их уникальные идентификаторы.

## Простая передача данных между экранами

Еще одним распространенным требованием в мобильных приложениях является возможность передачи данных между экранами. Это может быть достигнуто в Flutter путем передачи аргументов новому экрану при переходе к нему:

Navigator.push(

```dart
  context,
  MaterialPageRoute(builder: (context) => SecondScreen(data: 'Hello')),
);
```

В этом примере мы передаем строку ‘Hello’ виджету SecondScreen, используя аргумент data. Затем мы можем получить доступ к этим данным в виджете SecondScreen

```dart
class SecondScreen extends StatelessWidget {
  final String data;
  SecondScreen({required this.data});
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Second Screen')),
      body: Center(child: Text(data)),
    );
  }
}
```

В этом примере мы обращаемся к аргументу data, переданному SecondScreen в конструкторе, и используем его для отображения строки ‘Hello’ в пользовательском интерфейсе.

## Передача данных при навигации по имени

 При использовании навигации по имени данные на следующий экран передается  через специальный параметр arguments

Navigator.pushNamed(

```dart
    context,
    '/second',
    arguments: <String, String>{
      ‘data’: 'Hello'
      },
  );
```

В данном примере мы передаем Map<String, String> в котором по ключу data передается строка Hello.

В самом экране, на который мы переходим, мы должны получить эти аргументы с помощью класса ModalRoute:

```dart
final args = ModalRoute.of(context)!.settings.arguments as Map<String,String>
```

## Передача данных с onGenerateRoute

Вместо извлечения аргументов непосредственно внутри виджета вы также можете извлечь аргументы внутри функции onGenerateRoute() и передать их виджету.

Пример

```dart
void main() {
  runApp(MaterialApp(
    onGenerateRoute: (settings) {
      var path = settings.name?.split('/') ?? [];
      if (settings.name == '/') {
        return MaterialPageRoute(builder: (context) {
          return const HomePage();
        });
      }
      if ((path.length >= 3) && path[1] == 'second') {
        return MaterialPageRoute(builder: (context) {
          return SecondPage(data: path[2]);
        });
      }
      return MaterialPageRoute(builder: (context) {
        return const HomePage();
      });
    },
  ));
}
```

В onGenerateRoute мы передали функцию, которая получает в свои параметры settings, который содержит имя роута, который мы передаем в в вызове Navigator.pushNamed()

```dart
 var path = settings.name?.split('/') ?? [];
```

Разделяем весь путь на сегменты и в зависимости от переданного имени роута создаем и возвращаем сам роут. Здесь мы можем распарсить весь путь и передать параметры в конструктор нужной нам страницы.

Теперь когда мы вызовем 

Navigator.of(context)

```dart
                  .pushNamed('/second/hello'');
```

Мы перейдем на SecondPage и через его конструктор передадим строку hello

## Передача данных на предыдущий экран

Иногда нам необходимо открыть страницу, например с какой нибудь формой, дать пользователю ее заполнить и закрыть страницу, вернув введенные данные на первый экран.

Для этого в методе pop есть параметр Result, в который мы можем передать любой объект.

```dart
void pop<T extends Object?>([T? result])
```

Пример:

В первом экране мы должны добавить код для получения результата, для этого вызовем метод pushNamed и присвоим возвращаемое значение в переменную result.

Ключевое слово await означает, что метод pushNamed ассинхронный и нам нужно дождаться, когда он вернет результат. 

```dart
final result =  await Navigator.of(context).pushNamed('/second/hello');
```

Во втором экране мы добавим кнопку, которая закрывает окно и возвращает нам результат: 

```dart
class SecondPage extends StatelessWidget {
  const SecondPage({required this.data, super.key});
  final String data;
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(),
      body: Center(
          child: Column(
        children: [
          Text(data),
          ElevatedButton(
              onPressed: () {
                Navigator.of(context).pop('test');
              },
              child: const Text('Back'))
        ],
      )),
    );
  }
}
```

В данном случае мы возвращаем строку test. 

Так как экран можно в любой момент закрыть, не возвратив никакого результата, например свайпом или кнопкой назад, то возвращаемое значение всегда nullable, и может принимать значение null.

```dart
final result =  await Navigator.of(context).pushNamed('/second/hello');
```

Всё, что мы рассмотрели выше (push, pop, именованные маршруты, onGenerateRoute) — это так называемый **Navigator 1.0**, императивный API навигации, который был в Flutter с самого начала.

## Почему появился Navigator 2.0

Navigator 1.0 отлично подходит для простых мобильных приложений, но по мере роста Flutter (в первую очередь — выхода Flutter Web) у него обнаружился ряд ограничений:

- **Императивность.** Стек экранов меняется командами (push/pop), а не описывается как функция от состояния приложения. Это усложняет ситуации, когда стек должен зависеть от внешнего состояния — например, "если пользователь не авторизован, весь стек должен состоять из одного экрана логина".
- **Слабая поддержка deep linking и URL в вебе.** В Navigator 1.0 нет естественного способа отразить текущий экран в адресной строке браузера и, наоборот, построить стек экранов по адресу, введённому пользователем. Именованные маршруты и onGenerateRoute — это обходные пути, а не полноценное решение.
- **Кнопка "Назад" в браузере.** Она должна синхронизироваться со стеком Navigator, а в императивной модели за этим приходится следить вручную.
- **Восстановление состояния.** Операционная система (особенно Android) может убить и восстановить процесс приложения, и в этот момент стек экранов нужно восстановить — Navigator 1.0 не даёт для этого декларативного описания.

Решением стал **Navigator 2.0** — набор API (`Router`, `RouterDelegate`, `RouteInformationParser`, `RouteInformationProvider`), появившийся в Flutter 1.22, который делает навигацию **декларативной**: стек экранов — это функция от текущего состояния приложения, а не последовательность императивных команд.

## Navigator 2.0: декларативный подход

В основе Navigator 2.0 лежат три сущности:

- **RouteInformationParser** — превращает информацию из URL (или из системы восстановления состояния) в объект-конфигурацию приложения (например, `AppRoutePath`) и обратно.
- **RouterDelegate** — на основе текущей конфигурации строит виджет `Navigator` со списком `Page` (актуальный стек экранов). Именно здесь описывается, *что показывать*, а не *как туда попасть*.
- **Router** — виджет, который связывает парсер, делегата и провайдера информации о маршруте и подключается к `MaterialApp.router`.

Пример: два экрана (список фильмов и деталь фильма), где номер фильма отражается в URL как `/detail/42`.

```dart
// Конфигурация — описывает "где мы находимся"
class AppRoutePath {
  final String? movieId;
  AppRoutePath.home() : movieId = null;
  AppRoutePath.detail(this.movieId);
  bool get isDetail => movieId != null;
}
```

```dart
// Парсер — URL <-> конфигурация
class AppRouteInformationParser extends RouteInformationParser<AppRoutePath> {
  @override
  Future<AppRoutePath> parseRouteInformation(
      RouteInformation routeInformation) async {
    final uri = routeInformation.uri;
    if (uri.pathSegments.length == 2 && uri.pathSegments[0] == 'detail') {
      return AppRoutePath.detail(uri.pathSegments[1]);
    }
    return AppRoutePath.home();
  }

  @override
  RouteInformation restoreRouteInformation(AppRoutePath path) {
    return RouteInformation(
      uri: Uri.parse(path.isDetail ? '/detail/${path.movieId}' : '/'),
    );
  }
}
```

```dart
// Делегат — конфигурация -> стек Page
class AppRouterDelegate extends RouterDelegate<AppRoutePath>
    with ChangeNotifier, PopNavigatorRouterDelegateMixin<AppRoutePath> {
  @override
  final GlobalKey<NavigatorState> navigatorKey = GlobalKey<NavigatorState>();

  String? _selectedMovieId;

  void showDetail(String movieId) {
    _selectedMovieId = movieId;
    notifyListeners(); // сообщаем Router, что конфигурация изменилась
  }

  void showHome() {
    _selectedMovieId = null;
    notifyListeners();
  }

  @override
  AppRoutePath get currentConfiguration => _selectedMovieId == null
      ? AppRoutePath.home()
      : AppRoutePath.detail(_selectedMovieId);

  @override
  Widget build(BuildContext context) {
    return Navigator(
      key: navigatorKey,
      pages: [
        MaterialPage(
          key: const ValueKey('home'),
          child: HomeScreen(onOpen: showDetail),
        ),
        if (_selectedMovieId != null)
          MaterialPage(
            key: ValueKey('detail-$_selectedMovieId'),
            child: DetailScreen(movieId: _selectedMovieId!),
          ),
      ],
      onPopPage: (route, result) {
        if (!route.didPop(result)) return false;
        showHome();
        return true;
      },
    );
  }

  @override
  Future<void> setNewRoutePath(AppRoutePath configuration) async {
    _selectedMovieId = configuration.movieId;
  }
}
```

```dart
// Подключение к приложению
class MyApp extends StatelessWidget {
  final _routerDelegate = AppRouterDelegate();
  final _routeInformationParser = AppRouteInformationParser();

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      routerDelegate: _routerDelegate,
      routeInformationParser: _routeInformationParser,
    );
  }
}
```

Стек экранов здесь целиком описывается методом `build` делегата как функция от поля `_selectedMovieId` — это и есть декларативность. Плата за это — заметно больше кода по сравнению с Navigator 1.0 даже для двух экранов.

## Navigator 1.0 против Navigator 2.0

| Критерий | Navigator 1.0 | Navigator 2.0 |
|---|---|---|
| Стиль API | Императивный (push/pop) | Декларативный (стек — функция от состояния) |
| Порог входа | Низкий, минимум кода | Высокий, много boilerplate-кода |
| Deep linking / URL в вебе | Слабая, через обходные пути | Полноценная поддержка "из коробки" |
| Кнопка "Назад" в браузере | Нужно синхронизировать вручную | Синхронизируется автоматически через Router |
| Управление стеком снаружи (например, по auth-состоянию) | Неудобно | Естественно — стек пересобирается при каждом notifyListeners |
| Восстановление состояния | Не предусмотрено | Поддерживается через RouteInformationParser |

**Что выбрать?** Для небольшого мобильного приложения без веб-версии и без сложных сценариев (deep linking, ветвление стека по состоянию авторизации) Navigator 1.0 обычно достаточно и заметно проще в поддержке. Navigator 2.0 в "сыром" виде почти никто не пишет вручную именно из-за объёма boilerplate-кода — на практике поверх него берут библиотеку-обёртку, самая популярная из которых — **go_router**.

## go_router

**go_router** — официальный пакет от команды Flutter (входит в пакет `flutter_packages`), который реализует Navigator 2.0 "под капотом", но даёт разработчику декларативный, но при этом компактный API, похожий по духу на именованные маршруты Navigator 1.0.

Преимущества go_router:

- Маршруты описываются декларативно, одним списком `GoRoute`, а не тремя отдельными классами.
- Поддержка deep linking и URL в вебе работает "из коробки", без ручной реализации `RouteInformationParser`.
- Параметры пути (`:id`), query-параметры и произвольные объекты (`extra`) для передачи данных между экранами.
- Редиректы (`redirect`) — удобно для сценариев вида "не авторизован — перекинуть на /login".
- Вложенные маршруты и `ShellRoute` для постоянного UI (например, `BottomNavigationBar`), который не пересоздаётся при переходах между вкладками.

Чтобы подключить go_router, добавляем зависимость в `pubspec.yaml`:

```yaml
dependencies:
  go_router: ^18.0.2
```

## Один пример в трёх вариантах

Ниже — одно и то же приложение (список фильмов → деталь фильма по id, с отражением id в пути) реализовано тремя способами, чтобы сравнить их напрямую.

### Вариант 1 — Navigator 1.0

```dart
MaterialApp(
  initialRoute: '/',
  onGenerateRoute: (settings) {
    final uri = Uri.parse(settings.name ?? '/');
    if (uri.pathSegments.length == 2 && uri.pathSegments[0] == 'detail') {
      return MaterialPageRoute(
        builder: (_) => DetailScreen(movieId: uri.pathSegments[1]),
      );
    }
    return MaterialPageRoute(builder: (_) => const HomeScreen());
  },
)
```

Переход на экран деталей:

```dart
Navigator.of(context).pushNamed('/detail/$movieId');
```

### Вариант 2 — Navigator 2.0

Используются классы `AppRoutePath`, `AppRouteInformationParser` и `AppRouterDelegate`, показанные выше, подключённые через:

```dart
MaterialApp.router(
  routerDelegate: _routerDelegate,
  routeInformationParser: _routeInformationParser,
)
```

Переход на экран деталей:

```dart
routerDelegate.showDetail(movieId);
```

### Вариант 3 — go_router

```dart
final router = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => HomeScreen(
        onOpen: (id) => context.go('/detail/$id'),
      ),
    ),
    GoRoute(
      path: '/detail/:id',
      builder: (context, state) => DetailScreen(
        movieId: state.pathParameters['id']!,
      ),
    ),
  ],
);

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(routerConfig: router);
  }
}
```

Переход на экран деталей:

```dart
context.go('/detail/$movieId');
```

Обратите внимание: во всех трёх вариантах итоговый URL один и тот же (`/detail/42`), но количество кода, необходимого для его получения, сильно различается — от одной функции `onGenerateRoute` в Navigator 1.0, через три отдельных класса в чистом Navigator 2.0, до одного списка `GoRoute` в go_router. Это и есть причина, по которой go_router стал стандартом де-факто для новых Flutter-проектов.
